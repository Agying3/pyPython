# tools/ —— 维护工具

这里的脚本**不是 pyPython 的一部分**，是维护这个仓库用的辅助工具。

## 和 ADR-0001 的关系

ADR-0001 定死了解释器本体「纯 Python、**无第三方库**」。
这里的工具**同样遵守**这条约束 —— 不是被迫的，是刻意的：

画个性能图就 `pip install matplotlib`，是在打自己的脸。
而 SVG 本来就是一串 XML 文本，用标准库拼字符串就能生成，
这条路比装绘图库还短。

`tests/test_wiki_examples.py` 会**盯着这一点**：只要
`make_perf_chart.py` 里出现 `import matplotlib` / `numpy` / `PIL` 之类，
文档回归立刻报红。

## make_perf_chart.py

生成性能对比图，输出 `docs/perf.svg`。

```
python tools/make_perf_chart.py             # 测量 + 出图
python tools/make_perf_chart.py --dry-run   # 只测量，不写文件
```

### 为什么要画"范围"而不是"一根柱子"

实测 14 轮采样（每轮 300 回合）：

| 被测对象 | 范围 | 离散度 |
|---|---|---|
| pyPython 自身 | 244 ~ 279 微秒 | **14%** |
| 基线 A（timeit） | 0.368 ~ 0.85 微秒 | **120%** |
| 基线 B（exec） | 20 ~ 35 微秒 | **59%** |
| 慢 A 倍数 | 462 ~ 743 倍 | 12.5% |
| 慢 B 倍数 | 6.9 ~ 12.9 倍 | **58%** |

基线 A / B 抖得厉害，是因为它们本身只有零点几微秒 ——
**GC 一次、系统调度一次，分母就能翻倍**。

所以画"一根精确的柱子"是撒谎。图上画的是**中位数 + 实测范围**，
采样轮数和"数字会漂移"的声明直接印在图里。

这跟 ADR-0001 要求"两个基线都报、如实标注哪个没达标"是同一条原则。

### 版面踩坑记录

**#1 右侧结论栏压住了第三根柱子。**
第一版把结论文字框放在绘图区右侧内部（x 从 `plot_w - 246` 开始），
而第三根柱子（基线 B）的中心在 x=725 —— 正好撞上，
"21.2" 和 "需求「慢 ≥2 个数量级」" 叠在一起。

修法：给结论栏留**独立边距**（`MR = 260`），绘图区不再占用那一段。
验证方式不是肉眼看截图，是解析 SVG 算每个 `<text>` 的包围盒，
检查有没有水平区间相交 —— 见下。

**教训**：没有渲染器时，"看起来对"不等于对。
用几何自检（解析 XML + 算包围盒）能替代肉眼。

### 改了图之后怎么验

1. 跑 `python tools/make_perf_chart.py`
2. 跑 `python tests/test_wiki_examples.py` —— 会检查图存在、能解析、
   画了三个对象、标了"未达标"、声明了漂移
3. 想肉眼看，可以用 Edge 无头模式转 PNG：
   ```
   msedge --headless --screenshot=perf.png --window-size=900,560 \
          --default-background-color=FFFFFFFF file:///.../docs/perf.svg
   ```
