# ADR-0010：文档站用 GitHub Pages 手写静态复刻，不装博客系统

- 状态：Accepted
- 日期：2026-10-01
- 关联：ADR-0001（纯 Python、无第三方库）、ADR-0009（三值逻辑）
- 影响文件：`gh-pages` 分支（`index.html`、`posts/*.html`、
  `assets/style.css`、`assets/img/`、`tools/check_site.py`）、`README.md`

## 背景

项目此前只有三处能读到文档：`README.md`、`wiki/`（11 页）、`docs/decisions/`。
三处都是**仓库内**的形态——访客得先点进 GitHub、再点进某个标签页。

需要一个"门面"：打开一个网址就能看到文章列表，像博客一样。
用户明确要求参考 `xing.xo.je` 的观感，并说明站主同意参考。

抓下来看，那个站用的是 [Argon](https://github.com/solstice23/argon-theme)
（v1.3.5，⭐5589，GPL-3.0）。它是**WordPress 主题**。

## 决策

### 1. 不装 WordPress，手写静态页复刻观感

**这是本 ADR 的核心取舍。**

Argon 是 PHP，跑在 WordPress + MySQL 上。而 **GitHub Pages 只能托管静态文件**
——放不了 PHP，也放不了数据库。所以"部署 Argon"在 Pages 上**物理上做不到**。

但更硬的理由是第二条：**ADR-0001 定死「纯 Python、无第三方库」。**
解释器里连 `json`/`pickle` 都否掉了（ADR-0003 自己写了长度前缀编码），
文档站却装一整套 WordPress，比解释器里引 matplotlib 还过分。

所以只复刻**观感**，不引任何依赖：

| Argon 的做法 | 这里的做法 |
|---|---|
| `argon_css_merged.css`（358 KB） | 手写 `style.css`（约 430 行） |
| PHP 模板拼 HTML | 手写 HTML |
| MySQL 存文章 | HTML 文件本身 |
| WordPress 插件做深色模式 | 20 行 JS + `html.darkmode` |
| 主题更新走 wp-admin | `git push` |

**代价**：加一篇文章要手写一个 HTML 文件，没有后台。
**接受这个代价的原因**：本项目一共就打算写十来篇，而且
"文档站没有构建步骤"本身符合这个项目的性格。

**未采用：Hugo / Hexo 静态博客框架。** 它们能上 Pages，也有 Argon 的移植版，
但要引入 Node.js 工具链。同上，与 ADR-0001 的气质冲突。

### 2. 复刻的是观感，不是代码

没有复制 Argon 的任何 CSS/JS（它是 GPL-3.0，抄进来会有授权牵连）。
只参考了**视觉参数**，这些是配置值不是代码：

```
--card-radius: 15px          圆角（照搬原站）
主色: #009688                青色（**不是** Argon 默认的 #5e72e4）
背景: 两张 2560x1440 壁纸，交叉淡入
```

### 3. 主色用 #009688，不用 Argon 默认值

抓原站时先看到 `<meta name="theme-color" content="#5e72e4">`，
一度以为主色是那个蓝紫。**这是错的**——`#5e72e4` 是 Argon 的
**默认值**，站点在自定义里覆盖成了 `#009688`：

```css
--color-border-on-foreground-deeper: #009688;
```

教训同类于 ADR-0009 第五条：**meta 标签里的值是"默认"，不是"实际"。**
要读真正生效的那一处（这里是自定义 CSS 里的变量覆盖），不要读声明处的值。

### 4. 背景用两张壁纸交叉淡入，不用 JS 换图

原站的做法值得照搬，它比 JS 切换简单且自带过渡：

```css
body::before { background-image: url("img/day.jpg");   opacity: .7; }
body::after  { background-image: url("img/night.jpg"); opacity: 0;  }
html.darkmode body::before { opacity: 0;   }   /* 交叉 */
html.darkmode body::after  { opacity: .7;  }
html.darkmode body::before,
html.darkmode body::after  { filter: brightness(.65); }
```

两张图叠在固定层上，只切 `opacity`——**深色模式自动换成夜景图**，
不需要任何 JS 参与选图。

### 5. 壁纸文件名改成 ASCII

原图名是 `【恋风】20260425120451-scaled.jpeg` 和 `卧室-夜晚-小新-scaled.jpg`。
中文名进 URL 会变成一长串百分号编码，`background-image: url(...)`
在部分环境下会解析失败。重命名为 `day.jpg` / `night.jpg`。

**图片本身没有改名以外的任何处理**，也没有压缩。

## 踩过的坑

### #35「gh-pages 孤儿分支第一次提交前切走，整个分支连同文件一起消失」

- **曾出现**：`style.css` 写完、还没提交，就 `git checkout master` 去写本 ADR；
  回来发现 `gh-pages` 分支不存在了，**CSS 和 ADR 正文全丢**，只能重写
- **根因**：`checkout --orphan` 建的分支**没有父提交**，
  在第一次 commit 之前不算真实分支。切走时 Git 直接丢弃它，
  **工作区也一并清掉**。`git stash -u` 也救不回来——
  新文件在孤儿分支上从未被 `add`，stash 抓不到
- **为什么特别值得记**：我开这个分支前**刚写下**这条坑的**反面**
  （"建完分支后 master 的文件还在，此时 `git add -A` 会把整个解释器提交进去"）。
  我防住了误提交，却没防住反向的"全丢"
- **修法**：建完孤儿分支**立刻提交一次**，再做别的。
  完整顺序是：**先清干净 → 再放文件 → 立刻提交 → 然后才切走**
- **教训**：一个操作有"两个方向的错"时，只防住一边不算防住

### #36「被 JS 挑战保护的站点，HTTP 200 不等于拿到内容」

- **曾出现**：抓 `xing.xo.je` 时 `Invoke-WebRequest` 一直返回 200，
  但内容长度**恒为 837 字节**，一度以为站点是个空 SPA
- **根因**：站点前面挂了层 `aes.js` 挑战（`Server: openresty`）。
  首次访问只返回一个壳，要求浏览器算出 `__test` cookie 再跳 `?i=1`。
  用户给的 `?i=1` 就是这个挑战的跳转参数
- **修法**：用无头 Edge 执行 JS 跟随跳转，拿到真实 DOM（96 KB）
- **副产品**：`robots.txt` 反而没被拦，从 `Disallow: /wp-admin/`
  直接暴露了它是 WordPress 的事实——**绕不过去的门前，先看看有没有侧门**
- **教训**：**长度恒定的 200 是反爬的典型特征**。正常页面长度会变

### #37「Move-Item 失败后提交，提交信息在撒谎」

- **曾出现**：`Move-Item _check_site.py tools/check_site.py` 失败
  （`tools/` 目录在 gh-pages 上还不存在），但命令串里没检查退出码，
  紧接着的 `git add -A && commit` 照常执行，
  于是提交信息说"加 tools/check_site.py"，实际提交的是根目录的 `_check_site.py`
- **根因**：PowerShell 的 `Move-Item` 报错不中断后续语句（不是 `set -e` 语义）
- **修法**：`git mv` 到正确位置 + `commit --amend` 修正
- **教训**：**提交信息里写的路径，和实际提交的路径，是两件事。**
  多步命令要检查中间步骤的结果

## 验证

`tools/check_site.py`（在 gh-pages 分支上），**26 项全过**：

| 组 | 覆盖 |
|---|---|
| CSS | 主色是 `#009688`、声明里没混进 `#5e72e4`、两张壁纸都有引用、毛玻璃、15px 圆角、深色压暗 |
| 每页 | 有 `<title>`、有深浅色按钮、偏好会持久化 |
| 链接 | **所有本地 `href`/`src` 指向的文件真实存在**（静态站最常见的死法是 404） |

**关键设计**：检查"没混进 `#5e72e4`"时**必须先把 CSS 注释剥掉**再查。
否则会误报——因为注释里**应该**出现这个默认值，那是在说明"别抄它"。
（第一次写就误报了，同 ADR-0008 第三条：报告失败之前先确认测的是什么。）

另外用无头 Edge 真的渲染了一遍，确认首页和文章页都能出内容、
代码块转义正确、控制台无 JS 报错。**模型看不了图，所以改用
"渲染后抓 DOM + 程序化断言"来验收**，不靠肉眼。

## 遗留

- **Pages 需要在网页上手动开启**（Settings → Pages → Source 选 `gh-pages`）。
  命令行做不了这一步。
- **四篇文章是 wiki 内容的"叙事版本"**，不是复制。同一件事实用博客口吻重讲，
  与 wiki 不重复。但**两边数字必须一致**——性能数字改了要同步改，
  这是个新的双副本风险点（本项目第 13 类）。
- 没有分页、没有搜索、没有 RSS。十来篇文章用不上。
- 深色模式偏好存在 `localStorage`，首次访问跟随系统偏好。
- 首页的「4 文章 / 3 分类 / 10 ADR」是**手写的数字**，
  加文章或加 ADR 时要记得改——又一处双副本。
