# ADR-0010：文档站用 GitHub Pages 手写静态复刻，不装博客系统

- 状态：Accepted
- 日期：2026-10-01
- 关联：ADR-0001（纯 Python、无第三方库）、ADR-0003（长度前缀编码）、
  ADR-0009（三值逻辑）
- 影响文件：`gh-pages` 分支（`index.html`、`posts/*.html`、
  `parts/layout.html`、`content/*.body.html`、`assets/style.css`、
  `assets/img/bg.jpg`、`tools/build_site.py`、`tools/check_site.py`、
  `tools/falsify_site_checks.py`）、`README.md`

> **本记录在 2026-10-01 做过一次事实更正**，见下面的第 3 条与 `#41`。
> 决策本身没变（仍然是"静态复刻、不装博客系统"），
> 改的是一个**记错了的事实**（主题色），以及新增的几条踩坑记录。

## 背景

项目此前只有三处能读到文档：`README.md`、`wiki/`（11 页）、`docs/decisions/`。
三处都是**仓库内**的形态——访客得先点进 GitHub、再点进某个标签页。

需要一个"门面"：打开一个网址就能看到文章列表，像博客一样。
用户要求参考 `xing.xo.je` 的观感，并说明站主同意参考。

抓下来看，那个站用的是 [Argon](https://github.com/solstice23/argon-theme)
（v1.3.5，⭐5589，GPL-3.0）。它是**WordPress 主题**。

## 决策

### 1. 不装 WordPress，手写静态页复刻观感

**这是本 ADR 的核心取舍。**

Argon 是 PHP，跑在 WordPress + MySQL 上。而 **GitHub Pages 只能托管静态文件**
——放不了 PHP，也放不了数据库。所以"部署 Argon"在 Pages 上**物理上做不到**。

但更硬的理由是第二条：**ADR-0001 定死「纯 Python、无第三方库」。**
解释器里连 `json`/`pickle` 都否掉了（ADR-0003 自己写了长度前缀编码），
文档站却装一整套 WordPress，比解释器里引 matplotlib 还过分。

所以只复刻**观感**，不引任何依赖：

| Argon / WordPress 的做法 | 这里的做法 |
|---|---|
| `argon_css_merged.css`（358 KB） | 手写 `style.css`（约 680 行） |
| PHP 模板拼 HTML | `tools/build_site.py` 拼（纯标准库） |
| MySQL 存文章 | HTML 正文文件 + Python 里的元数据 |
| WordPress 插件做深色模式 | 20 行 JS + `html.darkmode` |
| 主题更新走 wp-admin | `git push` |

**未采用：Hugo / Hexo 静态博客框架。** 它们能上 Pages，也有 Argon 的移植版，
但要引入 Node.js 工具链。同上，与 ADR-0001 的气质冲突。

### 2. 布局只有一份，加一个构建脚本

> 这一条是 2026-10-01 改版时补的。第一版是**手写 7 个 HTML**，
> 每个页面各带一份左栏。

左栏、导航、页脚在每个页面上都一样。手写 7 份就是**同一份东西抄 7 遍**，
改一处忘一处就漂移——本项目为这类问题栽过十几次
（见 `docs/decisions/README.md` 的"一条贯穿多份记录的教训"），
而且几乎全是静默失效：不报错，只是不对。

所以改成：

```
parts/layout.html        唯一一份布局（左栏、导航、页脚、深色模式脚本）
content/*.body.html      各页正文
tools/build_site.py      拼装（纯标准库，无依赖）
```

顺带把「文章数 / Wiki 页数 / ADR 篇数」这些数字**算出来**，不再手写 ——
手写的数字同样会漂移。第一版的首页就把这三个数写死在 HTML 里，
现在是从 git 和内容里数出来的。

**代价**：加一篇文章要写一个正文文件、在元数据里加一条、再跑一次
`python tools/build_site.py`。
**接受这个代价的原因**：换来"布局只有一份"，而且构建脚本是纯标准库的，
仍然符合 ADR-0001。

**未采用：保存时自动构建的监视进程。** 十来篇文章，手动跑一次就够了。

### 3. 主题色是 `#5e72e4`，不是 `#009688`

> **这一条在 2026-10-01 更正过。** 原来这里写的是"主色用 `#009688`"，
> 那是**错的**，见 `#41`。决策（用原站的主题色）没变，改的是这个值。

抓原站时先看到 `<meta name="theme-color" content="#5e72e4">`。
全文**只有一处** `--themecolor` 声明：

```css
:root {
    --themecolor: #5e72e4;
}
```

所以主题色就是 **`#5e72e4`（紫）**。

原站的**注释**里出现过 `#009688`：

```css
/*也可以用类似于--color-border-on-foreground-deeper: #009688;这样的命令*/
```

那是**示范语法用的例子**，不是配置。我一度把它当成了真实值，
于是整个站点的导航栏、栏目标题、文章标题都做成了青色。
直到截图跟参考图并排看才发现颜色不对。

**教训**：这个坑和 ADR-0009 第五条、以及本 ADR 开头那条"meta 是默认值
不是实际值"是同一类——**不要猜哪个值生效，读真正生效的那一处**。
而"真正生效的那一处"不包括注释。

### 4. 背景用壁纸，深浅色共用一张

原站用两张图交叉淡入（浅色一张、深色一张）。这里改成**一张**：

```css
body::before {
    background: url("img/bg.jpg") center/cover no-repeat;
    opacity: .7;
}
html.darkmode body::before {
    opacity: .55;
    filter: brightness(.62);
}
```

**为什么不用两张**：原站深色模式那张是另一个角色的图，用户明确说
"我要波奇酱"，不要那张。所以深浅色共用波奇酱，深色只压暗。

### 5. 壁纸文件名用 ASCII

原图名是 `【恋风】20260425120451-scaled.jpeg`。中文名进 URL 会变成
一长串百分号编码，`background-image: url(...)` 在部分环境下会解析失败。
改名为 `bg.jpg`。

**图片本身没有改名以外的任何处理**，也没有压缩。

## 踩过的坑

### #35「gh-pages 孤儿分支第一次提交前切走，整个分支连同文件一起消失」

- **曾出现**：`style.css` 写完、还没提交，就 `git checkout master` 去写本 ADR；
  回来发现 `gh-pages` 分支不存在了，**CSS 和 ADR 正文全丢**，只能重写
- **根因**：`checkout --orphan` 建的分支**没有父提交**，
  在第一次 commit 之前不算真实分支。切走时 Git 直接丢弃它，
  **工作区也一并清掉**。`git stash -u` 也救不回来——
  新文件在孤儿分支上从未被 `add`，stash 抓不到
- **为什么特别值得记**：我开这个分支前**刚写下**这条坑的**反面**
  （"建完分支后 master 的文件还在，此时 `git add -A` 会把整个解释器提交进去"）。
  我防住了误提交，却没防住反向的"全丢"
- **修法**：建完孤儿分支**立刻提交一次**。完整顺序是：
  **先清干净 → 再放文件 → 立刻提交 → 然后才切走**
- **教训**：一个操作有"两个方向的错"时，只防住一边不算防住

### #36「被 JS 挑战保护的站点，HTTP 200 不等于拿到内容」

- **曾出现**：抓 `xing.xo.je` 时 `Invoke-WebRequest` 一直返回 200，
  但内容长度**恒为 837 字节**，一度以为站点是个空 SPA
- **根因**：站点前面挂了层 `aes.js` 挑战（`Server: openresty`）。
  首次访问只返回一个壳，要求浏览器算出 `__test` cookie 再跳 `?i=1`
- **修法**：用无头 Edge 执行 JS 跟随跳转，拿到真实 DOM（96 KB）
- **副产品**：`robots.txt` 反而没被拦，从 `Disallow: /wp-admin/`
  直接暴露了它是 WordPress —— **绕不过去的门前，先看看有没有侧门**
- **教训**：**长度恒定的 200 是反爬的典型特征**

### #37「Move-Item 失败后提交，提交信息在撒谎」

- **曾出现**：`Move-Item _check_site.py tools/check_site.py` 失败
  （`tools/` 目录在 gh-pages 上还不存在），但命令串里没检查退出码，
  紧接着的 `git add -A && commit` 照常执行，
  于是提交信息说"加 tools/check_site.py"，实际提交的是根目录那份
- **根因**：PowerShell 的 `Move-Item` 报错不中断后续语句
- **修法**：`git mv` 到正确位置 + `commit --amend`
- **教训**：**提交信息里写的路径，和实际提交的路径，是两件事**

### #38「脚本移进 tools/ 之后，自检自己崩了」

- **曾出现**：`FileNotFoundError: 'H:\pyPython\tools\posts'`
- **根因**：`ROOT` 从 `__file__` 直接推，隐含假设"脚本就在站点根目录"。
  脚本最初确实写在根目录，后来才移进 `tools/`
- **修法**：往上退一级。验证方式是从项目外跑一遍，确认不依赖 cwd
- **教训**：**移动文件时，路径推导要跟着改**，而且这类错误不会报错，
  只是找不到东西

### #39「自检漏掉了新加的页面，还显示全绿」

- **曾出现**：加了 `wallpapers.html` 之后跑自检，仍然全过 ——
  因为页面清单写死了 `["index.html"] + posts/*`
- **根因**：页面清单是手写的，加页面时不会自动带上
- **修法**：改成扫根目录和 `posts/` 下所有 `.html`（并跳过 `_` 开头的临时文件）
- **教训**：**"检查范围"本身也是一份需要同步的副本。**
  写死范围，等于给自己发了一张"看不见新东西"的通行证

### #40「`git add -A` 把 master 的 `__pycache__` 提进了 gh-pages」

- **曾出现**：准备提交时 `git status` 有 72 条，其中 **62 条是 `.pyc`**
- **根因**：切换孤儿分支**不会**清理未跟踪文件。master 上跑过测试留下的
  `__pycache__`、以及 `pypython_idle/` 整个目录都还在磁盘上
- **修法**：加 `.gitignore`
- **教训**：这是孤儿分支那个坑的**第三个变种** ——
  先是"会把 master 文件误提交"，再是"分支会整个消失"，
  现在是"未跟踪的垃圾也会被一起提交"

### #41「把 CSS 注释里的示例当成真实配置，主色抄错了」

- **曾出现**：主题色写成 `#009688`（青），实际是 `#5e72e4`（紫）。
  整个站点配色错了一轮，直到截图和参考图并排看才发现
- **根因**：原站自定义 CSS 的**注释**里有这么一句：
  `也可以用类似于 --color-border-on-foreground-deeper: #009688; 这样的命令`。
  那是注释，不是配置
- **副产物**：写这条教训时，我在**同一段注释里打出了注释的结束符号**，
  内层那个符号把外层注释提前关掉，**半张样式表变成无效 CSS**。
  修好之后又在旁边写下"不要这样做"，结果**又打了一次那两个字面字符**，
  于是又断了一次。所以现在这段说明里一律用「」代替
- **修法**：把值改成 `#5e72e4`；自检里加"注释必须配对且不嵌套"
- **教训**：**注释里的值不是配置。** 同一个教训在这个文件里应验了三次，
  第三次是自检脚本曾经**断言了错误结论**（它当时也写着"主色是 #009688"）——
  **一个断言了错误结论的测试，比没有测试更坏，它会替错误背书**

### #42「按文件名认定图片内容，把蜡笔小新当成了波奇酱」

- **曾出现**：把 `卧室-夜晚-小新-scaled.jpg` 直接当成"蜡笔小新的深夜卧室"，
  写进 ADR、照搬上站当深色背景，**从没验证过图里画的是什么**。
  用户要的是波奇酱
- **根因**：文件名不是内容。而且当时模型看不了图，只能猜
- **修法**：换成波奇酱那张；把 7 张候选做成预览页让用户自己挑
- **教训**：**文件名不等于内容。** 看不了图就不要对图里是什么下结论——
  要么问，要么把候选摆出来让人挑

### #43「构建脚本数本地目录，把『ADR 1 篇』显示到了页面上」

- **曾出现**：侧边栏统计显示「ADR 1 篇」，实际有 10 篇
- **根因**：脚本数的是**本地文件系统**上的 `docs/decisions/`，
  而脚本跑在 gh-pages 上——那个目录本该不存在，
  但之前 `#35` 的残留把 `0010` 这一个文件提交到了 gh-pages，
  于是目录存在、里面只有 1 个文件，数出来就是 1。
  原来的兜底逻辑只处理"目录不存在"，处理不了"目录存在但是错的"
- **修法**：改成问 `git ls-tree master` 要文件清单，不再相信本地目录
- **教训**：**"本地有这个目录"不等于"这就是权威内容"。**
  跨分支的脚本尤其如此——本地那份很可能是别的分支的残留

### #44「左栏的选中高亮一直不生效，但谁也不报错」

- **曾出现**：首页/文章页的左栏里，当前那一项没有高亮
- **根因**：构建脚本给导航和左栏都输出 `class="active"`，
  但 CSS 里左栏那条规则写的是 `.current`。选择器不匹配 = 静默失效，
  页面照常渲染，只是那一项没变色
- **修法**：CSS 两个类名都认
- **反向验证时又发现检查太松**：第一版检查写成
  `".active" in css or ".current" in css`，把 `.active` 改名后照样通过
  （因为 `.current` 还在）。改成"先读出生成器用的是哪个类名，
  再要求 CSS 必须有那一个"，并且**用正则认死 `,` 或 `{` 结尾**——
  否则 `.side-nav a.active:hover` 里的子串会把检查骗过去
- **教训**：**选择器和生成代码之间的约定，是一份隐式的"两份副本"。**
  改类名时两边都要动，而漏改的那一边不会报错

### #45「自检报了一堆不存在的链接，其实链接是好的」

- **曾出现**：5 个页面全报"本地链接/资源都存在"失败，
  缺的是 `index.html#posts`
- **根因**：检查时没把 `#锚点` 剥掉，直接拿整串当文件名去找
- **修法**：先切掉 `#` 和 `?` 再判存在
- **教训**：**报告失败之前，先确认测的是不是你以为的那件事** ——
  这句话本项目记了三次（ADR-0008、ADR-0009、ADR-0010），
  这次轮到我自己的检查脚本犯

## 验证

`tools/check_site.py`，**31 项全过**：

| 组 | 覆盖 |
|---|---|
| CSS | 主色是 `#5e72e4`、声明里没有注释里的示例色、背景图有引用、毛玻璃、15px 圆角、深色压暗 |
| CSS 合法性 | 注释符号配对、没有嵌套注释、花括号平衡 |
| 一致性 | 左栏选中态选择器与构建脚本输出的类名一致 |
| 每页 | 有 `<title>`、有深浅色按钮、偏好会持久化 |
| 链接 | **所有本地 `href`/`src` 指向的文件真实存在**（静态站最常见的死法是 404） |

**关键设计**：检查"主色"时**必须先把 CSS 注释剥掉**再查。
否则注释里提到别的颜色会误报（第一版就误报过）。

`tools/falsify_site_checks.py` 做**反向验证**：把三个坑故意重犯一遍，
确认自检真的会红：

```
[红了 OK] 主色抄成注释里的 #009688
[红了 OK] CSS 注释被提前结束
[红了 OK] 左栏选中态选择器改名
反向验证：3 项红了 / 0 项没红
```

**测不出问题的测试等于没测**（同 ADR-0008 第三条）。

另外用无头 Edge 真的渲染并**截图看过**：首页和文章页的布局、
配色、标签、图片都确认过。在此之前模型看不了图，
只能靠"抓 DOM + 程序化断言"间接验收；
现在能看图了，才发现配色一直抄错（`#41`）。

## 遗留

- **四篇文章是 wiki 内容的"叙事版本"**，不是复制。同一件事实用博客口吻重讲，
  与 wiki 不重复。但**两边数字必须一致**——性能数字改了要同步改。
  这是本项目第 13 类"多份副本"，目前**没有测试盯着**。
- 没有分页、没有搜索（搜索按钮指向 GitHub 代码搜索）、没有 RSS。
  十来篇文章用不上。
- **构建脚本从 git 的 master 读 Wiki/ADR 数量**。如果哪天不使用 git
  （比如导出成压缩包），会回退到硬编码的常量并在构建时打印提示。
- 深色模式偏好存在 `localStorage`，首次访问跟随系统偏好。
- 左侧「功能」那个标签页是**装饰**，点了没反应（参考图里有两个标签）。
- 吉祥物用的是项目的字「炑」，不是插画。
