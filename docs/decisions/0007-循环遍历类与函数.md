# ADR-0007：第二版语言构造——循环、遍历、函数、类

- 状态：Accepted
- 记录日期：2026-02-15
- 决策依据：用户指令「现在改设计循环、遍历、类、def了」，并在若干具体问题上逐条选择
- 实施情况：已实施（解释器回归 33/33、错误路径 29/29、空行 16/16、关键字同步全绿、IDE 回归全绿）
- 关联记录：扩展 [ADR-0002](0002-语法简化-实现不简化.md)（语法简化，实现不简化）到新构造；
  新增两类"两层不一致"缺陷（#23、#24），续 [ADR-0006](0006-标识符支持中文.md) 的清单

## 背景

第一版 pyPython 只有：`x「1」` 赋值、`$(x)` 输出、`~`/`·` 比较、`if`/`else`、列表、字符串、
并排相乘。没有循环、没有函数、没有类——写不出任何需要"重复"或"复用"的程序。

用户要求补齐四件东西：**循环、遍历、类、def**。

`「」` 已经被赋值占用了，所以块不能再用括号包——**沿用 `if` 的缩进块**，
这是唯一不用发明新符号的选择。

## 决策

### 1. 新增语法（全部沿用"没有冒号、缩进划块"的既有风格）

```
while 条件              循环。没有 break / continue
   语句

for 变量 in 表达式       遍历。只能遍历列表和字符串
   语句

def 名字(参数, ...)      函数。参数无默认值
   语句
   return 表达式        return 可省略（省略时返回 0）

class 名字               类
   def __init__(参数)    构造器
       self.属性「值」
   def 方法()
       return self.属性

全局 名字                在函数里声明"这个赋值是改全局的"
```

调用/实例化：

```
p「点(1, 2)」           直接调类名就是建对象
$(p.长度())             方法调用
```

### 2. 关键字共 10 个

`if` `else` `while` `for` `in` `def` `return` `class` `self` `全局`

**刻意不加** `break` / `continue` / `try` / `raise` / `pass` / `lambda` / `import`。
每加一个关键字，下文第 5 节那 6 份副本就多一处要同步的地方。

### 3. 作用域：Python 模式

用户在"全局作用域"和"Python 模式"之间选择了 **Python 模式**：

- **读**：内层找不到就找外层（局部帧 → 全局帧）
- **写**：`名字「值」` 默认创建/覆盖**局部**变量 —— 所以递归能正常工作
- **改全局**：必须显式写 `全局 名字`

用户在选择前问了"别的编程语言是怎么写的"（Python / Rust / Go / C）。
如实回答：这四门语言**都是**"每次调用独立的局部 + 全局可变"，
两者不是互斥关系。我最初把选项 A 描述成"全局作用域"是**不准确的**，已当面纠正。

### 4. 递归：支持，但限制深度

用户选择「能递归，但限制深度（推荐）」。

### 5. `self` 的处理

- 构造器名字用 `__init__`（用户选择）
- 实例化直接调类名 `点(1, 2)`（用户选择方案 A；
  `点「1, 2」` 被用户否决，理由"看起来太费劲了，可读性差"）
- **`self` 不写进参数表**（`def __init__(x, y)`），但**两种写法都必须能跑**
  —— 照 Python 习惯写 `def __init__(self, v)` 也得工作。
  `self` 永远绑定到真实调用者实例。

### 6. 实现风格：新代码写简洁

用户指令「这部分写简洁点」。第一版的"每个动作都绕三个类"的风格**不套用到新代码上**，
但既有的抽象层（正则校验层、Registry、真值格、11 层优先级、`reify()`、
手搓二进制、全角 `⟨⟩`）**一个都不删**。

## 备选方案

- **用 `「」` 包块**（`while 条件「 ... 」`）：否决。`「」` 已经是赋值符号，
  再占用会导致 `while` 和赋值无法区分。
- **引入 `{ }` 划块**：否决。本语言的美学是全角符号，引入 ASCII 花括号破坏一致性，
  而且要新增一对括号的匹配规则。
- **`self` 隐式且禁止显式书写**：否决。用户要求两种写法都能跑。
- **构造器叫 `构造` 而非 `__init__`**：用户选择了 `__init__`。
- **不加 `全局`，默认写全局**：否决。那样递归会立刻坏掉
  （每次调用都覆盖同一个变量）。

## 后果与风险

收益：

- 语言从"只能写直线代码"变成**图灵完备**（`while` + 变量足够）
- 递归可用（实测 `阶乘(5)`=120、`fib(10)`=55）
- 类/实例/方法/属性可用，实例之间互不干扰

成本与风险：

- **6 份关键字副本要手工同步**（见下）。这是本项目"两套真相"风格的固有代价，
  已用 `STATEMENT_KEYWORDS` 常量消掉其中一类漂移。
- 递归深度上限是**实测出来的魔法数字**，不是设计值（见 #21）。
- 没有 `break`，跳出循环只能靠让条件变假——用户没有要求，故不加。

## 本次修掉的真实缺陷

### #21　`MAX_DEPTH = 200` 是**假保护**

`MAX_DEPTH` 和 `self.depth` 在第一版就**声明了但从未真正生效**。
第二版把深度检查接上之后，写了个"无限递归必须报我们自己的错"的测试，结果拿到的是
Python 原生的 `RecursionError`。

实测（二分）：`196` 层可以，`197` 层抛 `RecursionError`。
原因：pyPython 的**一层**递归要烧掉约 5 个 Python 栈帧
（`_execute` → `_evaluate` → `_eval_binop_node` → `_eval_call2` → `invoke`），
Python 默认上限 1000 帧，所以约 196 层就撞墙——**`MAX_DEPTH=200` 从来轮不到执行**。

修法两道防线：

1. `MAX_DEPTH` 降到 `120`（实测安全线以内，留余量给更复杂的函数体）
2. `evaluate_source` 捕获 `RecursionError`，翻译成自己的炑错误，不让原生异常泄漏

### #22　`全局「0」` 的报错信息指向 `if`

错误信息写死成"这里需要一个缩进的语句块（if 后面必须跟缩进）"，
而这句是在只有 `if` 能开块的年代写的。现在有五种能开块的关键字，
且用户真正写错的地方常常与块无关。改成中性描述并列出全部五种。

（附带发现：这条报错是 v2 测试用例**自己写错了源码**才触发的——
`全局` 后面必须跟变量名。测试已修。）

### #23　空行吞掉全部 `DEDENT`，块永远不结束　**【本次最有价值的发现】**

```python
class 点
    def __init__(x, y)
        self.x「x」

def 累加(xs)          ← 被当成还在 class 体内
    return 1
```

删掉那个空行，程序立刻正常。

**根因（插桩实测 token 流得出，不是猜）**：`_measure_indent()` 判定空行时，
**把行尾的换行符也一起吃掉了**。而"把 `at_line_start` 置回 `True`"的代码
**只在主循环的 `if char in "\r\n"` 分支里**。换行符被吃掉 → 那个分支永不执行
→ 空行的**下一行**被当成"行中间" → **整段缩进比较被跳过，一个 `DEDENT` 都不产出**。

实测 token 流对比：

```
有空行  → ... NEWLINE, KW_DEF, ...                    ← 一个 DEDENT 都没有
无空行  → ... NEWLINE, DEDENT, DEDENT, KW_DEF, ...    ← 正确
```

更隐蔽的是：下一次 `_measure_indent` 量到的是**再下一行**（`return 1`，宽度 4），
所以错得"看起来很合理"，肉眼审不出来。

**为什么第一版没暴露**：那时能开块的只有 `if`，而 `else` 紧跟块尾、中间一般不放空行，
这条路径几乎走不到。加了 `def`/`class` 之后，"顶层语句之间空一行"
成了最常见的排版习惯，立刻踩到。

**修法**：`_measure_indent` 只吃到**换行符之前**为止，把换行符留给主循环，
由主循环照常产出 `NEWLINE` 并把 `at_line_start` 置回 `True`。

### #24　补全扫不到类名和函数名

`autocomplete.collect_identifiers` 只认 `名字「` 这一种形式，
所以 `class 点` / `def 累加` 定义出来的名字**永远补不出来**。
加两条正则分别抓 `class 名` 和 `def 名`。

（`pypython_idle/autocomplete.py` 一行里已经有 `ord(...) > 127` 的判断，
中文名字本身能补；缺的只是"扫不到定义"。）

## 诚实记录：测试写错的三次

本次有几轮"失败"其实是**测试自己的问题**，不是产品缺陷。如实记下，避免误判：

1. **`__init` 少写一个下划线**（5 处）。我写成 `def __init()`，
   于是构造器根本不存在。解释器报"类没有定义 `__init__`"是**对的**。
2. **`run()` 把空列表当"必须有输出"**。两个正确行为（无输出）被报成失败。
3. **`is_block_opener()` 喂错 offset**。它的 `lo` 语义是"取 `lo` 位置**之前**
   那条完整语句"，我连续试了三种摆法都对不上，连 `if` 都返回 `False`。
   最后改走**真实编辑器按回车**来验证，6 个关键字全部正确。

第 3 条是本次的方法论收获：**当一个 API 反复测不出预期时，
先怀疑自己的调用姿势，改用端到端路径验证**——比继续调参数更快到真相。
