# ADR-0003：值编码改用长度前缀，废弃分隔符切分

- 状态：Accepted
- 记录日期：2026-02-14
- 决策依据：实测缺陷（`#13` / `#15`）驱动的修复；用户要求加字符串与列表后必须能跑通
- 实施情况：已实施
- 关联记录：解决了 `pypython.py` 的 `#12` / `#13` / `#15`

## 背景与证据

`Registry`（符号表）把值序列化成字符串存进列表，是项目"数据转换"抽象层的主要来源。
最初只有数字，编码极简：

```
N:2
```

加入字符串和列表时，最初沿用了最自然的写法——**分隔符拼接**：

```
S:"abc"           字符串：带转义
L:[N:1,N:2]       列表：逗号 join，方括号包裹
```

随后实测出两个必然的缺陷（不是偶发，是设计缺陷）：

- **`#13` 嵌套列表数据全丢**
  `$([1, [2, [3]]])` 输出成 `[1, 0, [0]]`。
  内层列表编码后**本身含逗号**（`L:[N:2,L:[N:3]]`），
  被外层 `split(",")` 一刀切开，变成残缺片段，正则匹配失败。
- **字符串元素被切坏**
  `["a,b", "c"]` 变成 `["a", 0, "c"]`——字符串里的逗号被当成了元素分隔符。
- **同一个兜底分支连犯两案**：`decode` 匹配失败时**不报错、返回 0**。
  该分支在只有数字时是"友好"，有了多类型后变成"静默吞掉类型"（`#12`）。

修复过程还暴露第三个问题（`#15`）：改用个数前缀后，
`L2:N:1,N:2,` 中**除第一个元素外每个前面都顶着逗号**，
游标未跳过前导逗号，切出空片段并抛异常。修的时候还必须让
"跳过的长度计入消耗量"，否则游标漂移。

结论：**分隔符方案在多类型 + 嵌套 + 内容含分隔符的情况下无法自洽**，
补丁式修补只会不断引入新的边界问题。

## 决策

值编码统一采用**长度/个数前缀**，元素边界由**类型自身**界定，不依赖任何分隔符：

| 类型 | 编码 | 说明 |
|---|---|---|
| 数字 | `N:2` | 保持原样 |
| 字符串 | `S<长度>:<原样内容>` | 如 `S3:abc` |
| 列表 | `L<个数>:<元素1>,<元素2>,...` | 元素各自递归编码 |

配套约束：

1. **不再需要转义**。字符串按长度精确截取，内容含逗号、方括号、引号、
   反斜杠都不会产生歧义。这比转义方案更笨，但更不容易错。
2. **`decode` 与 `encode` 必须严格对称**。任何不对称都会静默产生错值，
   因此这条是修改该文件时的首要检查项。
3. **禁止"解不出来就返回默认值"的静默兜底**。匹配失败一律抛异常，
   由解释器层转成带位置的「炑」（`#16` 即为此而加）。
   静默兜底在设计上是宽容，在多类型下是灾难。
4. 列表仍用逗号连接元素（可读性），但**逗号不再承担解析语义**——
   它只是分隔，真正的边界来自每个元素自己的编码。

## 备选方案

- **继续用分隔符 + 转义**（Python repr / JSON 风格）：
  能修好字符串含逗号的问题，但**嵌套列表的切分歧义依然存在**，
  除非写一个真正的递归下降编码解析器——那等于在此处再实现一个小解析器。
  判定为成本更高且更易错。
- **不用字符串编码，直接把 Python 对象存进列表**：
  能彻底避免这一切。但**这恰好摧毁了本项目的核心抽象**——
  "值 → 字符串 → 列表 → 反序列化"是泬账本的主要来源，
  也是"故意把高效的东西低效化"的体现。不予考虑。
- **用 `pickle` / `json` 标准库**：与"不依赖现成工具"的项目前提冲突，
  且会绕过手写编解码这一抽象层。

## 后果与风险

收益：

- 嵌套、混合类型、含特殊字符的内容全部正确，已用探针逐项验证。
- 编码方案从"靠约定"变成"靠结构"，边界问题不再依赖运气。

成本与风险：

- **编码串对人类不再可读**：`S3:abc` 尚可，深嵌套列表会变成
  `L2:N:1,L1:N:2,` 这类难以肉眼核对的形式。调试时不能直接看出内容。
- **`_decode_one` 的游标推进逻辑是脆弱点**。它必须同时正确处理
  "前导逗号跳过量"和"元素自身消耗量"，任一处算错都会导致静默错位。
  见 `#15` 的完整说明。
- **列表元素个数与实际内容不一致时不会报错**（`L5:` 后面只有 2 个元素），
  会读到空串并抛异常——行为是"炸"而不是"静默错"，属于可接受方向。

## 受影响代码
