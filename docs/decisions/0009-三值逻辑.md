# ADR-0009：三值逻辑（真 / 假 / 未知）

- 状态：Accepted
- 日期：2026-02-14
- 关联：ADR-0003（值编码）、ADR-0007（IDE 关键字表副本）
- 影响文件：`pypython.py`、`pypython_idle/`（6 处）、`pypython_ide.py`、
  `tests/test_v4_three_valued.py`、`tests/test_keyword_sync.py`

## 背景

第四版要给 pyPython 加**三值逻辑**。这是这门语言唯一一个不是"套壳 CPython"
的功能，也是用户明确的创新点。

三个值是：

| 值 | 含义 | 不是什么 |
|---|---|---|
| `TRUE` | 已观测，为真 | |
| `FALSE` | 已观测，为假 | |
| `MAYBE` | **尚未观测** | 不是 `None`，不是错误，不是随机 |

关键区分：**第三态不是"介于真假之间"，而是"信息缺失"。**

用户给的类比（不进代码注释）：约人出来，`TRUE` 是约到了，`FALSE` 是约不到，
`MAYBE` 是**消息发出去了还没回**。没回不等于失败，也不等于成功。

## 决策

### 1. 第三态用关键字 `未知`，不用变量名

`未知` 写成关键字（`KEYWORDS["未知"] = "KW_UNKNOWN"`），跟 `self` 同类：
它是**值**，不是语句、不是运算符。

**为什么不做成内置变量名**（比如让用户直接用 `MAYBE` 这个名字）：
那样用户写一句 `未知「5」` 就能把状态覆盖掉。用户要求"这个状态必须被语言
保留"，而能被覆盖的名字保留不住任何东西。

已验证：`未知「5」` 报错，覆盖不掉。

**为什么用中文**：本语言符号层已经是全角的（`「」$~·`），"未知"读起来就是
它的意思，不用翻译。

**约束：`未知` 绝不进 `STATEMENT_KEYWORDS`。** 它不能开一条语句——
加进去会让 `if 未知` 里的 `未知` 被当成新语句的开头（`not` 踩过同样的坑）。

### 2. 原来的数值档 MAYBE 改名为 LIMBO

**这是本次唯一的破坏性改动。**

`TruthinessChamber` 原来有四档：

```
FALSE / HOPELESS / MAYBE / TRUE
```

其中 `MAYBE` 的含义是"数字落在 **0 和 1 之间**"（0.5 → MAYBE）。
它和"未观测"完全不是一回事——0.5 是**确定的** 0.5，不是"还没回消息"。

不改名的后果：语言里有两个都叫 MAYBE 但意思不同的东西，
三值逻辑永远说不清。所以这一档改名 `LIMBO`。

**改名的影响面极小**：`verdict_index()` 和 `is_true()` 都是**按下标**工作的
（`is_true` 写死 `== 3`），不看字面名字。所以逻辑一行都没改，
只是换了字符串。已验证。

唯一可见变化：`$(0.5)` 现在印 `0.5 ⟨LIMBO⟩ 0b0`，以前印 `⟨MAYBE⟩`。

```python
TRUTH_LATTICE = ["FALSE", "HOPELESS", "LIMBO", "TRUE"]
```

### 3. 真值表按表实现，不靠短路推断

Kleene 三值逻辑：

| AND | 右:T | 右:F | 右:M |
|---|---|---|---|
| **左:T** | T | F | M |
| **左:F** | F | F | **F** |
| **左:M** | M | F | M |

| OR | 右:T | 右:F | 右:M |
|---|---|---|---|
| **左:T** | T | T | **T** |
| **左:F** | F | F | M |
| **左:M** | T | M | M |

| NOT | |
|---|---|
| T → F | F → T | **M → M** |

两条最容易写错的格子：

- **`FALSE and MAYBE = FALSE`**：确定的假能压过未知
- **`TRUE or MAYBE = TRUE`**：确定的真能压过未知
- 反过来压不过去：`TRUE and MAYBE = MAYBE`、`FALSE or MAYBE = MAYBE`

`tri_and` / `tri_or` / `tri_not` 三个函数**必须写成显式的表**
（`if left == ... ` 逐格比较），不能写成 `if not left: return left` 这种短路推断——
那样 `假 and 未知` 和 `未知 and 假` 会走出不同结果，而它们**必须相同**。

### 4. 短路求值和真值表并存

两者不冲突，因为回答的是不同问题：

- 短路是**求值策略**：右边还要不要算
- 真值表是**语义**：算出来是什么

一致性可以验证：

```
假 and 未知：左边确定为假 → 短路（不算右边），查表也得假     ✓
未知 and 假：左边不是假   → 不短路（算右边），查表也得假     ✓
```

**两条路都到假，所以求值顺序不影响结果。** 这是三值逻辑必须具备的性质——
否则同一个式子会时真时假。

实现上，短路条件只看"确定为假/确定为真"，**MAYBE 不在短路条件里**
（未知定不死任何东西）。

### 5. 未知会传染，且绝不猜

未知参与任何运算，结果都是未知：

| 运算 | 结果 |
|---|---|
| `未知 + 1` | `MAYBE` |
| `未知 > 1` | `MAYBE` |
| `未知 ~ 1` | `MAYBE` |
| `not 未知` | `MAYBE` |
| `[未知][0]` | `MAYBE` |
| `{"a": 未知}["a"]` | `MAYBE` |
| `f(未知)` | `MAYBE` |

**为什么不猜**：`未知 + 1` 是几？猜 0 就是 1，猜 1 就是 2。哪个都不是用户能
确认的答案。传递未知才是诚实的做法。

**绝不使用 `random`。** 底层是二进制机器，任何随机都是伪随机。
用伪随机冒充未知，等于把"我不知道"偷偷换成"我掷了个骰子"。
已验证：连续 8 次求值结果完全一致。

### 6. 控制流碰到未知：静默观测

**`if`**：条件为 `MAYBE` 时，**then 和 else 都不执行**。

这不是 bug，是三值逻辑的应有之义：未知时不该替用户选任何一边。
"不执行任何代码块，只记录到账本，不报错、不随机、不跳过"。

**`while`**：条件为 `MAYBE` 时**不进循环体**，记一笔账后退出。

为什么不"先跑一圈看看"：循环体可能改变条件依赖的变量，而"未知"的意思正是
**我们不知道**它会不会变。替用户赌一把，就是拿伪随机冒充未知。

**一定要记账，不能纯静默。** 如果两边都不跑又什么都不说，用户只会看到一个
不动程序，分不清"遇到未知"和"程序坏了"。账本让未知**可见**，
但不让它**被处理**。

### 7. 账本记三件事（用户指定）

每次静默观测必须写清楚：

1. **哪个变量是未知**
2. **哪一行代码碰到了它**
3. **这个未知有没有传染到后面的运算**

第 3 件最难。第一版实现（下称"爬树版"）是**事后回头走一遍 AST**，
逐个 `IdentNode` 去问当前值是不是 MAYBE，再看条件表达式的节点类型
（裸变量算没传染、`LogicNode` 算已传染）。

**爬树版有个硬伤：它只能看"当前这一行"。** 下面这种就追不出来：

```
x「未知」
y「x + 1」      ← 未知传给了 y
z「y * 2」      ← 又传给了 z
if z            ← 只能记"z 是未知"，记不出它是从 x 一路来的
```

### 8. 真溯源：污染标记（taint）

第二版实现改成给值打**污染标记**，标记跟着值走。这样才能回答
"这个未知最初从哪来、经过了谁"。

**标记必须存在编码里，不能挂在对象上。** 这一条是实测出来的：
`Registry` 存的是 `encode()` 出来的**字符串**，不是 `PyPyValue` 对象，
所以任何挂在对象属性上的标记过一次赋值就没了。

```
原始对象 .my_marker = taint-from-x
encode 之后: 'N:5'
decode 回来的对象 .my_marker = None      ← 丢了
```

于是编码加一个**可选前缀**：

```
Tx>y|N:5         ← 值 5，污染路径 x→y
a+b|S3:abc       ← 字符串，两个独立来源 a 和 b
N:5              ← 没污染，**和以前一模一样**
```

约束：**没污染的值编码完全不变**。这是向后兼容的关键，
也是"旧测试、旧输出格式全部不受影响"的原因。

#### `>` 和 `+` 是两种不同的关系

| 连接符 | 含义 | 例子 |
|---|---|---|
| `>` | **流过去**：值从左边那个变量算出来，存进了右边 | `x>y` = "x 传给了 y" |
| `+` | **两个独立来源汇合**：不同的未知一起参与了运算 | `a+b` = "a 和 b 各自被污染过" |

**这个区分不是装饰，是防撒谎。** `c「a + b」`（a、b 是各自独立的未知）
如果画成 `a → b → c`，账本就在谎称"a 引起了 b"，而 a 和 b 毫无关系。
用户按这个信息去查会查到一个不存在的因果链。

所以渲染也分开：

```
x → y → z → w              一条传递路径
a → c 与 b → c             两个独立分支，都流进了 c
```

#### 踩过的坑：合并时不能拆开已有的路径

`#33`

- **曾出现**：三层以上的传递链全都退化成"两个独立来源"
- **现象**：`x → y → z` 显示成 `x 与 y`，第四层的 `w` 直接消失
- **根因**：`_merge_taint` 把每个操作数的污染串**拆开重拼**了。
  `z「y * 2」` 里 y 的污染是 `"x>y"`（一条路径），拆成 `"x"`、`"y"`
  再拼就变成 `"x+y"`——路径被降级成了并集，链就断在这里
- **修法**：合并时**整体保留**每个操作数的污染串，只在它们之间加 `+`。
  只有真的有两个不同操作数时才出现 `+`
- **已验证**：四层传递现在完整显示 `x → y → z → w`

同一次改动里还踩过一次反向的坑：我一度"为了不把并集错说成路径"
而让赋值**跳过**接名字，结果三层以上全断。正确的做法是**总是接**
（`c「a + b」` → `a>c+b>c`），因为 c 确实同时来自两支。

#### 标记的出生与生长

- **出生**（`_do_assign`）：值是未被命名的 `未知` → 盖上变量名
  （`x「未知」` → 标记 `"x"`）
- **生长**（`_do_assign`）：值已带标记 → 把变量名接到**每一支的末尾**
  （`x>y` 存进 z → `x>y>z`）
- **传染**（`_merge_taint`）：运算的操作数整体并入结果的标记

#### 提示指向源头，不是中间环节

账本最后一行提示用户怎么让分支确定下来。约束：**必须指向源头**。

`x` 未知导致 `z` 未知时，让用户去给 `z` 赋值没有意义——z 是算出来的，
赋值也盖不住 x 这个源头。所以提示取的是标记的**第一节**：

```
未知来源：z
传播路径：x → y → z
提示：若要确定分支，先给 x 赋一个确切的值；不确定就让它保持未知，语言不会替你猜。
```

### 9. 输出格式（用户指定，一个字都不能改）

```
炑：静默观测已触发（第X行），状态未知，未执行任何分支。
```

另外附明细行（我加的，因为光一行总括看不出那三件事）：

```
      未知来源：x
      传播路径：x → y → z → w
      传染情况：已传染 → 条件表达式（LogicNode）
      提示：若要确定分支，先给 x 赋一个确切的值；……
```

### 10. `truth_number()` 必须拦住未知

`truth_number()` 是"任何值 → 判真假用的数字"的映射。不拦未知的话
`float("MAYBE")` 会抛 `ValueError`，用户看到宿主的报错信息。

返回 **0.5**：既不是 0 也不是 ≥1，于是密室判成 `LIMBO`，
而 `is_true()` 对 `LIMBO` 返回 `False`。这样还没改成三值的旧控制流不会炸，
只会安静走"非真"那条路。

真正的三值判断在 `tri_from_value()` 里做。

## 踩过的坑

### #31「`未知 > 1` 抛出宿主 TypeError」

- **曾出现**：三值逻辑传染探针的"变量参与比较"用例
- **现象**：`TypeError: '>' not supported between instances of 'str' and 'int'`
- **根因**：`MAYBE` 在底层是一个普通字符串，走到 `_apply_operator` 的
  `left.raw > right.raw` 那一行时，就是 Python 在比较 `str` 和 `int`
- **修法**：在 `_concat_or_fail` 里，比较运算和算术运算之前**先查未知**，
  有未知直接返回 `MAYBE`。
  两处插入位置都很讲究：
  - **比较**：插在 `COMPARISONS` 分支开头
  - **算术**：必须插在 `left_is_text = isinstance(left.raw, str)` **之前**——
    排后面的话 `未知 + 1` 会被当成"字符串和数字相加"，
    报出一条跟真实原因毫无关系的炑错误
- **已验证**

### #32「`未知` 漏进字符串分支，被印成 `"MAYBE" ⟨TRUE⟩`」

- **曾出现**：`transmute_output` 加未知分支之前
- **根因**：`MAYBE` 是字符串，会掉进字符串分支；字符串按**长度**判真值，
  长度 5 ≥ 1 → 判成 `TRUE`。等于把"未知"说成了"真"
- **修法**：在字符串分支**前面**加未知分支，直接返回 `MAYBE ⟨MAYBE⟩`，
  **不经过密室**——密室只能判真假，而未知的意义正是"密室还没法判"
- **这是本设计最容易出错也最不能出错的一格**

## 关键字表的"语义分叉"

第四版只加了一个关键字 `未知`，但它跟第三版的 `and`/`or`/`not` 一样，
**在不同副本里有不同的归属**。改错的现象很难查，所以列表如下：

| 副本 | `未知` 要加吗 | 理由 |
|---|---|---|
| `pypython.py` `KEYWORDS` | **要** | 词法层要认出来 |
| `pypython.py` `STATEMENT_KEYWORDS` | **不要** | 它是值，不能开语句 |
| `pypython_idle/__init__.py` | **要** | 权威表 |
| `colorizer.py` | **要** | 要高亮 |
| `hyperparser.py` | **要** | 光标停在上面要认得出 |
| `autocomplete.py` | **要** | 否则用户不知道有第三态 |
| `calltip.py` | **要**（新卡片 `unknown`） | 语法提示 |
| `pyparse.py` `PYPYTHON_BLOCK_OPENERS` | **不要** | 加错的现象：写完 `未知` 回车多缩进一级 |
| `pypython_ide.py` | **要**（关键字 + 骨架两处） | 代理 IDE |

`tests/test_keyword_sync.py` 逐项盯着，漏一处或加错一处都会红。

### 自己写测试时踩的坑

`#34`

- **曾出现**：v4 测试第 11 组"每次静默观测都带提示"
- **现象**：断言恒为假，但账本里明明有"提示：……"那一行
- **根因**：我写成 `"提示" in obs.hint`。但 `hint` 字段里存的是**建议正文**
  （"若要确定分支……"），"提示：" 这个标签是 `ObservationLedger.lines()`
  渲染时才加的。查错了地方
- **教训**：和 ADR-0008 第三条一样——**报告失败之前，先确认测试测的是不是
  你以为的那件事**。这次是测试写错，不是代码错

## 遗留

- `MAYBE` 在输出里印成 `MAYBE ⟨MAYBE⟩`，有点啰嗦。改了会破坏用户
  指定的可辨认性，先留着。
- **`未知` 不能参与字符串拼接**：`未知 + "a"` 返回 `MAYBE`（被算术那段拦下）。
  这符合"传染"原则，但"未知 + 字符串是不是该报类型错"没细究。
- **污染标记不会消失**：一个值被污染过就永远是脏的，即使后来被赋了确定值。
  `x「未知」` `x「5」` 之后 x 仍然是脏的（标记跟着值走，而 5 是个新值，
  所以实际上 x 会变干净——但 `y「x」` 这种别名不会）。
  真正的"污点清除"需要显式机制，本版没做。
- **`while ... else`、`for ... else` 没有**，所以未知退出循环时没有 else 可跳过。
- 三值逻辑目前只作用于**控制流和逻辑运算**。比较/算术虽然会传染未知，
  但**不参与真值表**——`未知 ~ 未知` 返回 `MAYBE` 而不是 `TRUE`。
  这是刻意的（不确定的东西不能说自己等于自己，用户已确认保持），
  但没有对照实现。
- **`x ~ x` 保持 MAYBE**（用户明确选择）。理由：未知的东西不能声称自己
  等于自己。副作用是用户没办法写"这个值到底观没观测"的自反判断——
  要做那个得另加一个 `已观测(x)` 之类的内建，本版没有。
- **溯源粒度是变量，不是表达式**。`y「x + 1」` 的路径记成 `x>y`，
  中间那个 `+ 1` 不体现。要细到"经过哪些运算"需要给标记加运算痕迹，
  现在只加到"经过哪些变量"。
