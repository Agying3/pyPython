# ADR-0006：标识符支持中文，且正则层必须与扫描器一致

- 状态：Accepted
- 记录日期：2026-02-14
- 决策依据：用户实测发现中文变量名报错，选择「支持，修正则层」
- 实施情况：已实施（37/37 回归通过）
- 关联记录：修正了 [ADR-0002](0002-语法简化-实现不简化.md) 遗留的一处内部矛盾；
  与 [ADR-0005](0005-两种IDE实现并存.md) 的"两层不一致"是同一类问题的又两例

## 背景与证据

用户实测中文变量名时拿到：

```
LexError: 正则层拒绝了这个标识符 '数'
```

但**同一份代码里，补全能扫出中文变量名**——这说明系统内部对"中文能不能做标识符"
这件事有两套互相矛盾的答案。

查证结果，**两层规则打架**：

```python
# 词法扫描器（pypython.py 的 _scan_word）
while self._peek().isalnum() or self._peek() == "_":
    self._take()
# str.isalnum() 对中文返回 True —— 所以扫描器**会**把「数」整个吞下来

# 正则校验层（pypython.py 的 RE_IDENT）
RE_IDENT = re.compile(r"^[A-Za-z_][A-Za-z0-9_]*$")
# 只认 ASCII —— 于是同一批字符在这里被拒绝
```

而 IDE 侧的 `autocomplete.py`：

```python
RE_PYPYTHON_ASSIGN = re.compile(r"^\s*([A-Za-z_\u4e00-\u9fff][\w\u4e00-\u9fff]*)\s*\u300c")
```

**它是对的**（显式列出了中文区间）。所以补全能扫出 `数`，解释器却跑不了。

### 这不是单纯的功能缺失，是"报错位置错位"

扫描器放行 → 正则层拒绝，用户看到的是"正则层拒绝了这个标识符"。
这句话本身没错，但它描述的是**内部实现的分工**，而不是用户能理解的原因。
用户会疑惑：既然不让用中文，为什么补全会提示中文？为什么自动缩进认中文？

## 决策

1. **支持中文标识符**。理由：
   - 语言本身已经用了 `「」$~·` 这套全角符号。若标识符只能是 ASCII，
     那就是"符号用中文、名字用英文"的半吊子设计。
   - 扫描器**已经**支持了（`isalnum()` 的行为），改正则层是**让两层一致**，
     而不是新增能力。改动面最小。
   - `·`（不等号）是中文输入法下最容易误打的键。这类语言的使用者本来就在中文输入法里，
     变量名打中文是自然行为。

2. **正则层与扫描器必须保持一致**。新规则：

   ```python
   RE_IDENT = re.compile(r"^[^\W\d]\w*$", re.UNICODE)
   ```

   `[^\W\d]` = "是 `\w` 但不是数字"，正好对应 `isalnum() and not isdigit()`。
   `\w` 在 Unicode 模式下包含中文。

3. **不加"标识符允许哪些 Unicode 区块"的白名单**。
   `isalnum()` 就是规则，正则跟着它走。多一份白名单就多一处会漂移的地方
   ——本次 bug 的成因正是"两个地方各写各的规则"。

## 备选方案

- **改扫描器只认 ASCII，中文报错**：否决。用户明确选择支持；
  且那要改动扫描器的切分逻辑，风险比改正则大。
- **往 `RE_IDENT` 里显式列 `\u4e00-\u9fff`**：否决。
  那只能覆盖常用汉字区，日文假名、韩文、西里尔字母等仍会被拒，
  而扫描器全都放行——等于把同一个 bug 留一个更小的版本。
- **删掉正则校验层**：否决。ADR-0002 明确要求保留这层"多余的二次校验"
  作为刻意的复杂度，删掉会违背项目目标。

## 后果与风险

收益：

- 中文变量名可用，且与 ASCII 行为**完全一致**（回归对照过）
- 正则层的规则现在**能被一句话说清**：跟扫描器一样
- 报错位置回到扫描器层，用户看到的是"这里不该出现这个字符"这种能理解的信息

成本与风险：

- **`\w` 的行为随 Python 的 Unicode 数据库版本变化**。理论上不同 Python 版本
  对某个生僻字符的 `isalnum()` 结论可能不同。但扫描器用的是同一个
  `isalnum()`，所以**两层仍然一致**——这正是我们要的性质。
- `[^\W\d]` 这个写法可读性差。已加注释说明它等价于
  `isalnum() and not isdigit()`。
- **首字符的极窄差异**：扫描器允许首字符是任意 `isalnum()` 字符（含全角数字 `３`），
  正则层用 `[^\W\d]` 会拒绝全角数字开头。这个差异是**故意的**——
  全角数字开头做标识符本来就该报错，而且现在报错位置在扫描器层，信息更清楚。

## 受影响代码

- `pypython.py` / `RE_IDENT` —— 正则从 ASCII 白名单改为 Unicode 类
- `pypython.py` / `_scan_word` —— 未改，但它定义了"什么算标识符"的权威规则
- `pypython_idle/autocomplete.py` / `RE_PYPYTHON_ASSIGN` —— 已兼容，无需改动

## 验证

- 中文：单字、长名、中英混合、用在 `if`、存字符串、存列表 —— 全部通过
- ASCII 回归：单字母、普通名、下划线开头、带数字 —— 全部通过
- 该拒绝的仍拒绝：`1x`、`x-y`、`x.y`、`x;y`、`x = 1`
- 硬指标：`$(1+1)` 仍输出 `2 ⟨TRUE⟩ 0b10`
- 完整回归 **37/37**

## 记录：这是第 8 次"两层不一致"

本项目反复出现同一类缺陷——**同一个概念在两个地方各写一份规则，然后漂移**：

| 编号 | 位置 | 表现 |
|---|---|---|
| #I9 | colorizer 分组名 vs tag 名 | 高亮静默失效 |
| #I11 | `make_pat()` vs `self.prog` | 改哪都不生效 |
| #I14 | `FileList.EditorWindow` vs `PyShellFileList.EditorWindow` | 工厂替换无效 |
| #I18 | `_windowlist` vs `registry.callbacks` | 清空无效 |
| — | `trans` 表 vs `if ch in "([{"` | `「」` 不识别为括号 |
| — | `_chew_ordinaryre` vs `_study2` | 同上，第二处 |
| — | Help 文档"没用"vs `help.py` 真在读 | 差点弄坏 Help 菜单 |
| **本条** | **扫描器 `isalnum()` vs `RE_IDENT`** | **中文变量名报错** |

**共同特征：不发生异常，只是行为不对。**
因此不能靠"跑起来没报错"判断正确性，必须**读源码找出真正的读取点**，
或者**写一个会失败的对照测试**。
