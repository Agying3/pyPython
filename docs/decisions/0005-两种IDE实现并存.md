# ADR-0005：两种 IDE 实现并存 —— 运行时代理版与源码改造版

- 状态：Accepted
- 记录日期：2026-02-14
- 决策依据：用户要求「Python 的原生 IDE 源码抓下来改造」，并在了解两版差异后选择「直接先全做完」，即两版并存
- 实施情况：已实施（两版均可用）
- 关联记录：是 [ADR-0004](0004-IDE-寄生-IDLE-而非手搓.md) 的延伸；共同依赖 [ADR-0001](0001-pyPython-宿主与定位.md)

## 背景与证据

ADR-0004 确定了"寄生 IDLE、不改 idlelib 源码"的方针，产出了
`pypython_ide.py`（单文件，约 1300 行，运行时用**子类 + 类属性替换**
的方式改造 IDLE）。

用户随后要求「把 Python 原生的 IDE 源码抓下来改造」。这与前者有实质区别：

| | 运行时代理版 | 源码改造版 |
|---|---|---|
| 源码位置 | 系统 `Lib/idlelib/` | 项目内 `pypython_idle/` |
| 改造方式 | 运行时替换类属性 | **直接改源码文件** |
| 依赖系统 IDLE | 是 | 否 |
| 体积 | 1 个文件 | 60 个模块 20568 行 + 新增 6 个 |

用户明确要求"改源码"，而不是"保持原样只改入口"。

## 决策

1. **两版并存，不互相替代**：
   - `pypython_ide.py` —— 运行时代理版，单文件，作为**保底方案**
   - `pypython_idle/` —— 源码改造版，自带全部 IDLE 源码
2. **源码改造版拷贝全部 60 个核心模块**，跳过 `idle_test/`（14031 行测试）。
   理由：IDLE 模块间 import 极密（`editor.py` 依赖 20+ 个模块），
   只拷"用到的"会不断碰壁返工。
3. **改造只动"语言知识"相关的部分**，不动编辑器基础设施：
   撤销、查找、缩进、括号匹配、行号这些与语言无关的能力原样保留。
4. **入口统一指向 `startup.main()`**，**不使用** `pyshell.main()`。
   理由见下方"Shell 的处置"。
5. **新增的 6 个文件**（`startup.py` / `pypython_editor.py` /
   `pypython_colorizer.py` / `pypython_autocomplete.py` /
   `pypython_calltip.py` / 根目录 `pypython_idle_start.py`）
   全部带 `py` 前缀或独立命名，与拷来的上游文件**在文件名上可区分**。

### 逐模块改造清单

| 文件 | 改了什么 | 验证 |
|---|---|---|
| `colorizer.py` | `make_pat()` 重写：关键字表 `keyword.kwlist`→`["if","else"]`；内置名列表**清空**；删掉 match/case 软关键字与 r/u/f/b 字符串前缀；新增 `「」$` 与数字分支 | 28/28 |
| `autocomplete.py` | 补全词表换成 pyPython；删除 rpc 与 `eval("dir()")`；改为**扫缓冲区**取变量名；`get_entity` 改为抛 `NotImplementedError` | 25/25 |
| `hyperparser.py` | `keyword.iskeyword` → pyPython 关键字表；`_ID_KEYWORDS` 清空 | 25/25 |
| `calltip.py` | 从"函数签名提示"改为"**语法卡片**"；**整体删除** `get_entity` / `get_argspec`（它们用 `eval`+`inspect`） | 29/29 |
| `pyparse.py` | `is_block_opener`：行尾冒号 → 行首关键字；`_closere` 清空（pyPython 无 return/break）；`「」` 加入括号判定（**两处**） | 27/27 |
| `runscript.py` | 执行入口从 `compile()` + 子进程 → `pypython.evaluate_source()`；不再强制存盘 | 整机 34/34 |
| `__init__.py` | 插入项目根到 `sys.path`；新增权威关键字表 | — |
| `idle.py` / `__main__.py` | 入口指向 `startup.main()` | 三条入口全通 |
| `pyshell.py` | 仅修 8 处硬编码模块名，**其余未动且不被使用** | — |

### Shell 的处置

`pyshell.py` 有 1699 行，其中大部分是：`ModifiedInterpreter`（通过 rpc
把代码送进子进程）、子进程生命周期管理、调试器、栈查看器、
以及 `PyShell` 交互式 Shell（`>>>` 提示符、readline、历史）。

pyPython **不需要**其中任何一样：

- 它没有子进程，就是一个同进程的 Python 函数调用；
- 它每次重新解析整段源码，**没有"输入一句立刻求值"的语义**，
  套 `>>>` 只会让用户以为可以交互。

因此 `startup.py` **复刻 `pyshell.main()` 的装配段**
（`Tk(className=...)` → `fix_scaling` → 图标 → `fixwordbreaks` →
`fix_x11_paste` → `PyShellFileList` → `macosx.setupApp`），
但**不开 Shell**。

## 备选方案

- **改 idlelib 安装目录里的文件**：否决。污染原生 IDLE，Python 升级即丢失，难以回退。
- **只拷用到的模块**：否决。import 链太密，会反复返工。
- **保留 Shell 窗口**：否决。用户已在 ADR-0004 中确认"整段运行 + 输出面板"方案。
- **用 `pyshell.main()` 直接启动再打补丁**：否决。它会解析 `-c/-r/-s/-t/-n`
  等 Shell 开关并拉起子进程，打补丁的成本高于复刻装配段。

## 后果与风险

收益：

- 改造版**不依赖系统 IDLE**，可随项目分发，升级 Python 不受影响。
- 语言知识（关键字、补全词、缩进规则）现在**写在源码里**，
  读代码就能看到，不必去猜运行时替换了哪些类属性。

成本与风险：

- **两份真相变成四份**：关键字表现在存在于
  `pypython.py`、`colorizer.py`、`autocomplete.py`、
  `hyperparser.py`、`calltip.py`、`pyparse.py` 六处。
  改语言必须同步六处，漏一处不会报错，只会静默不一致。
- **与上游脱钩**：Python 升级后需手动合并，否则长期漂移。
  这是"抓下来改造"的固有代价，用户已知悉并选择。
- **`「」` 的括号识别有两处**（`_chew_ordinaryre` 的排除集、
  `_study2` 里的 `ch in` 判定）。只改一处会使括号判定"代码写了但从不执行"，
  不报错、不生效——这是本次实际踩到的坑。

### 本次踩到的坑（原型的两次同类错误之外，新增两条）

- **`run.py` 的 `sys.modules['idlelib.run']`**：模块自注册用字符串硬编码，
  自动替换相对 import 抓不到，直接 `KeyError` 导致 `pyshell` 起不来。
  同类还有 `pyshell.py` 的 `sys.modules['idlelib.pyshell']` 与子进程启动命令、
  `config.py` 的 `idlelib.testing` 标记。**共 8 处**。
- **`pyparse.py` 的 `「」` 括号识别有两个位置**：先改了 `trans` 表，
  实测 `stmt_bracketing` 里 `「」` 完全不出现，读源码才发现真正判定是
  `if ch in "([{"` 这样的**字面量比较，不查 trans 表**；
  补上之后仍不生效，因为 `_chew_ordinaryre` 会把 `「」` 当普通字符啃掉。
  **两次都"改了一个看起来该改的地方"**——与 ADR-0004 的
  #I11/#I12/#I14/#I18 是同一类错误，这是第 5、6 次。

### 验证方式的一再失误（记录以免重犯）

- 用**引号计数造桩**测 `is_char_in_string` —— 读 `editor.py` 才发现真实实现
  依赖**染色标签**，造桩等于把被测对象换成自己的猜想。
- 用**字符串匹配**查"还有没有 `eval`" —— 匹配到了自己写的删除说明**注释**。
  改用 AST 检查后通过。
- **测试位置写错**：`greeting「"hi"」` 只有 14 列，测试用了 `col 15`，
  误判为代码而非字符串。逐列打印 tag 才定位到。
- **测试期望写错**：`x` 光打一个字母挑不出语法卡片，期望却写成 `assign`。
- **测 `idle.py` 用了 `import pypython_idle.idle`** —— 该文件里是
  `if __name__ == "__main__"`，所以 `main()` 不执行，静默 `exit 0`。
  必须用真实命令行启动才是等价测试。

## 受影响代码

- `pypython_idle/` —— 整个包（60 个拷来的模块 + 6 个新增文件）
- `pypython_idle/startup.py` —— 启动装配，复刻 `pyshell.main()`
- `pypython_idle/pypython_editor.py` —— 主窗口，装配三个改造过的组件

- `pypython_idle/colorizer.py`、`autocomplete.py`、`hyperparser.py`、
  `calltip.py`、`pyparse.py` —— 语言知识所在
- `pypython_idle_start.py` —— 项目根便捷入口
