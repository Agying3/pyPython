# ADR-0002：语法简化为 pyPython-1，但实现复杂度全部保留

- 状态：Accepted
- 记录日期：2026-02-14
- 决策依据：用户选择「方案 A —— 语法简单，实现依然糟糕」，并逐条确认了新语法（「」赋值、`$(x)` 输出、`~`/`·` 比较、并排即相乘、缩进块、无分号）
- 实施情况：已实施
- 关联记录：取代了旧的三阶段 + 波兰式语法；与 [ADR-0001](0001-pyPython-宿主与定位.md) 共同定义项目性质

## 背景与证据

项目早期语法是刻意反直觉的：三阶段变量（`manifest` / `will be` / `yield`）、
波兰前缀表达式（`(+ a b)`）、强制括号、右结合运算、花括号语句块、分号结尾。

用户随后要求**语法要比 Python 更简单**。关键在于划清界限：
"简单"是指**用户少打字**，还是**整个项目变简单**？

证据：用户选择的是前者——语法简化，但所有泬（抽象）机制必须原样保留。
本次改造前后的差异可核验：

- 删掉的关键字：`manifest` / `will` / `be` / `yield`（`KEYWORDS` 现仅 `if` / `else`）
- 删掉的符号：`;` `{` `}` `=`（`SINGLE_SYMBOLS` 不再含它们）
- **未删**的机制：8 层以上的调用链、泬账本、真值格、Registry 字符串往返、
  11 层装饰性优先级层、每次访问节点的 `reify()`

一个有说服力的对照：改造**之后**调用链反而从 8 层涨到 9 层
（新增 `_eval_binop_node`，把中缀 `a + b` 伪装成波兰式 `(+ a b)` 再算）。
语法少打字符，机器多绕一步——这正是本决策的预期效果。

## 决策

1. **面向用户的语法尽量简单**，接近 Python 的直觉：
   - 赋值 `x「1」`（用「」代替 `=`）
   - 输出 `$(x)`（代替 `print`）
   - 比较 `~`（等于）/ `·`（不等于）/ `>` / `<`
   - `if` / `else` + 缩进块，无花括号、无分号
   - 并排即相乘：`(a + b) 2` == `(a+b)*2`，**仅在括号内生效**
2. **面向机器的复杂度一条不减**：泬账本、真值格、字符串往返、
   装饰性函数层、`reify()` 全部保留。简化语法**不得**成为删减抽象层的理由。
3. **允许语法与实现的复杂度呈反相关**——语法越简单，实现越应当啰嗦。
   新增语法糖时，优先考虑让它在解释器里多绕几圈。

## 备选方案

- **保留旧语法，只做美化**：未采用。用户明确要求语法比 Python 简单。
- **简化语法同时简化实现**（让项目变成正常的解释器）：
  未采用。这会瓦解项目的前提——它存在的意义就是"过程抽象"。
- **保留三阶段变量但把关键字改短**：未采用。三阶段本身是认知负担，
  而用户要的是简单语法。

## 后果与风险

收益：

- 语法门槛大幅降低，用户能直接读懂示例程序。
- 证明了一个有趣的性质：**语法简洁与实现臃肿可以完全解耦**。
  看代码的人会困惑——程序这么短，为什么跑得这么慢。

成本与风险：

- **`~` 与 `·` 在同一个键上**，中文输入法下极易打反，
  且**不会报错**（两者都是合法运算符），属于静默错误。
  用户明确选择保留该设计、不加输入法提示。记录为 `pypython.py` 的 `#2`。
- 旧语法节点（`ManifestStmt` / `WillStmt` / `YieldStmt` 及其解释器分支）
  成为**死代码**但仍保留。用户明确要求"留着，等哪天真的不碍事了再删"。
  依据是：孤立死代码不会主动伤人，而活跃代码才是风险源
  （见 `#10`——事故出在把新方法插进 `tokenize()` 中间，与死代码无关）。
- 「并排即相乘」的判定不能靠"解析器是否在括号内"实现，
  嵌套时会失效（见 `#6` / `#7`）。正确依据是"左侧操作数是否来自括号"。
  这是一个**易复发**的设计陷阱，修改表达式解析时必须注意。

## 受影响代码

- `pypython.py` / `KEYWORDS`、`SINGLE_SYMBOLS`、`RE_SYMBOL`：新符号集，
  注意符号定义散落在三处，改动需同步
- `pypython.py` / `Lexer.tokenize()`：缩进断句、`「」`/`[]` 内换行不断句
- `pypython.py` / `Parser._juxtapose()`：并排相乘，含 `#7` 的防复发说明
- `pypython.py` / `Parser._compare()`：`~` / `·` 的静默错误风险
- `pypython.py` / `Interpreter`：`_do_assign` / `_do_print` 新语句语义
- `pypython.py` / 文件头语言说明：已整段重写为 pyPython-1
- `pypython_ide.py` / `PYPYTHON_KEYWORDS` 等：IDE 侧**另抄了一份**语法表
