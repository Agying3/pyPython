# ADR-0008：第三版语言构造——下标、字典、逻辑运算、循环控制

- 状态：Accepted
- 记录日期：2026-02-15
- 决策依据：用户问「少了原版 python 的一些功能会不会缺失许多操作啊」，
  在我列出的缺口清单后面直接回「**都加**」（下标访问、break/continue、and/or/not、字典）
- 实施情况：已实施（v3 核心 90/90、IDE v3 48/48、既有 8 套回归**全部保持绿**，
  合计 10 个脚本全通过）
- 关联记录：续 [ADR-0002](0002-语法简化-实现不简化.md)（能少写的地方要多写）、
  [ADR-0007](0007-循环遍历类与函数.md)（第二版构造 + 关键字多副本）；
  新增四个"两层不一致"缺陷（#27、#28、#29、#30）

## 背景

第二版有了循环、遍历、函数、类之后，pyPython 仍然**写不出很多最基本的程序**：

- 列表只能整个用，不能取某一个元素 → 连"找最大值"都要绕
- 循环一旦开跑就只能等条件变假 → 不能在找到目标时提前停
- 没有 `and`/`or`/`not` → 复合条件没法表达（`1 < x < 10` 也不支持）
- 没有字典 → 想按名字查东西只能写两个平行列表

用户问这些缺失要不要补，我给了一份清单和建议顺序，用户回「都加」。
于是本版一次补齐四项。

## 决策

### 1. 四项新语法的**具体形式**（关键取舍）

| 功能 | 形式 | 为什么是这个形式 |
|---|---|---|
| 下标读 | `xs[0]`、`xs[-1]` | **复用已有的 `[` `]`**，不发明新符号 |
| 下标写 | `xs[0]「值」` | 复用赋值括号，与 `self.x「值」` 完全同形 |
| 字典字面量 | `{「"a"」: 1}` | 复用 `「」`（本语言里就是"引起来的东西"）+ `:` |
| 逻辑运算 | `and` / `or` / `not` | 用**单词**，不用 `&&` `\|\|` `!` |
| 循环控制 | `break` / `continue` | 光秃秃的单词，跟 `return` 一致 |

三个决策的理由展开：

**下标复用 `[` `]`。** 本语言没有别的候选——`「」` 被赋值占了，
`()` 是分组和调用。而且 `[` 在"表达式后面"这个位置本来就不可能是列表字面量
（`xs[0]` 里 `xs` 后面紧跟的 `[` 只能是下标），所以**位置本身就能区分**，
不需要新的消歧规则。

**逻辑运算用单词而不是符号。** 三个候选都试过：

- `&&` / `||` / `!`：`!` 和本语言的 `·`（不等号）视觉上太像，两个都是窄符号；
  而且中文输入法下打 `&` `|` 需要切键盘。
- `的` / `或` / `非`：中文更贴合语言风格，但 `and`/`or` 是编程里最常见的词，
  用中文会让从 Python 过来的人一时反应不过来。
- **选定 `and` / `or` / `not`**：`in` 已经是单词了（`for x in xs`），
  逻辑运算跟着走单词路线是一致的。

**`break` / `continue` 的合法性在解析期检查。** 写在循环外直接报错，
不等到运行到那一行。理由见下面的 #26。

### 2. 优先级：整个表达式链变长了

```
并排相乘  →  or  →  and  →  not  →  比较  →  加减  →  乘除  →  一元负号  →  原子
```

跟 Python 一致。**注意 `not` 在比较之下**，所以 `not a ~ b` 读作 `not (a ~ b)`。

`and` / `or` **短路**，并且返回**决定结果的那个操作数本身**（不是 1/0）：

```
0 or 5    →  5        3 and 4  →  4
```

这样 `x「y or 默认值」` 才能用。`not` 返回数字 `1` / `0`——本语言没有布尔类型。

### 3. 值的编码：新增 `D` 前缀

沿用 [ADR-0003](0003-值编码长度前缀.md) 的长度前缀风格：

```
D<对数>:<key1编码><value1编码>,<key2编码><value2编码>,...
```

**这里犯了一个错**（属于 #30 那次排查的副产品）：原生 `dict` 的 key 是**原始值**（字符串/数字），
而 value 是 `PyPyValue`。我第一版写成了对两者都调 `.encode()`，
于是字符串 key 报 `sequence item 0: expected str instance, bytes found`、
数字 key 报 `'int' object has no attribute 'encode'`。
修法是 key 也包一次 `PyPyValue(key)`。

### 4. 判真值：新增 `truth_number()`

本语言的规则是"**任何值都要经过真值密室**"，而密室只认数字。
原先各处写的是 `raw.decoded()`，而 `decoded()` → `magnitude()` → `float(raw)`
**只对数字成立**。字符串和列表能侥幸工作是因为它们的判真值走的是 `len()`
（在 `transmute_output` 里），绕开了 `decoded()`；
但 `if` 和逻辑运算直接调 `decoded()`，字典一进去就炸（#28）。

新增 `PyPyValue.truth_number()` 收拢这件事：

| 值类型 | 判真值用的数字 |
|---|---|
| 数字 | 它自己 |
| 字符串 | 长度 |
| 列表 | 元素个数 |
| 字典 | 键值对个数 |
| 函数 / 类 / 实例 | 0（一律判假） |

**函数那三个刻意给 0**，不按"参数个数/方法数"判——
那样 `if 某个函数` 会因为参数多而变真，太容易误解。

## 踩到的坑（四个"两层不一致"缺陷）

### #26　`break` 写在循环外，直到运行到才报错

第一版实现只管解析、不管上下文，循环合法性留给运行期的异常冒泡。
后果：一段**永远不会执行到**的 `break` 根本不报错。

**修法**：解析期维护 `self.loop_depth`，解析循环体时 +1（`try/finally` 保证还原），
解析 `break`/`continue` 时检查 `> 0`，否则当场 `ParseError`。

### #27　循环体里定义的函数，函数体里的 `break` 会打断**调用方**的循环

这是本次最有价值的一个发现，因为**它完全不报错，只是少循环了几圈**。

源码：

```
i「0」
while i < 3
    def f()
        break
    f()
    i「i + 1」
$(i)
```

修之前输出 `0`——外层 `while` 第一圈就被 `f()` 里那个 `break` 干掉了。

**根因**：`loop_depth` 是解析器的**一个字段**，进入函数体时没有清零。
于是"函数被写在循环体里"这件事让函数体内的 `break` 也成了合法，
而它在运行期抛出的 `BreakSignal` 一路冒泡，被**外层那个 `while`** 接住——
等于隔着函数边界打断了别人的循环。

**修法**：解析 `def` / `class` 体之前把 `loop_depth` 存起来、置 0，解析完还原。
**函数边界就是循环边界**——函数体里的 `break` 只能属于函数体**内部**的循环。
这跟 Python 的编译期检查一致。

**注意**：光在解析期修是不够的，运行时 `invoke` **不能**接 `BreakSignal`
（它只接 `ReturnSignal`）。否则函数里的 `break` 会被函数自己吃掉，
变成"静默地什么也不做"，那是另一种错。

### #28　`if 字典` 和 `not 字典` 抛 Python 的 `TypeError`

见上面第 4 节。**关键教训**：字符串和列表"能用"是**巧合**，不是设计——
它们恰好走了另一条不经过 `decoded()` 的路径。
新加一个类型时，"它能不能判真值"这件事必须**主动检查**，
不能因为"另一个容器类型没问题"就假设也没问题。

### #29　改 `RE_SYMBOL` 的时候把 `-` 漏掉了

我往字符类里加 `{` `}` `:` 时凭记忆重写了一遍，漏掉了原有的 `-`。
后果：**所有减法、负数全部报**「正则层拒绝了这个符号 '-'」——
阶乘、斐波那契、递归深度测试一起挂。

`-` 在这个字符类里必须放在**最后一位**（否则会被当成范围符，
比如 `+-\*` 会被读成"从 `+` 到 `*` 的范围"）。

**教训**：这类"一长串符号的字符类"靠肉眼核对是不可靠的，
必须跑会用到**每一个**符号的回归。这次是回归测试先发现的——
说明上一轮建的测试值这个钱。

### #30　嵌套下标写不进去，而且不报错

`m[0][1]「55」` 之后读 `m[0][1]` 还是老值。**两层根因**：

1. `_finish_assign_to` 把 `target.target` / `target.index` 拆开当
   "容器的根名字"和"下标"用。对单层下标没问题；对嵌套下标，
   `target.target` 本身是一个 `IndexNode`。
2. **更隐蔽的一层**：`PyPyValue.decode()` 的列表分支是**新建**一个 list
   （逐个 `append`）。而 `_eval_index` 为了满足"每次取下标都要序列化一遍"
   的要求，会把容器 `encode` → `decode`——
   于是 `_evaluate(m[0])` 返回的是**第 0 行的副本**。
   往副本里写、写完就丢，原列表一点没变，**而且不报任何错**。

**修法**：
- `IndexAssignStmt` 存**整个** target 节点（而不是拆开的容器和下标），
  运行期各自求值
- 赋值路径单独走 `_evaluate_container()`：它遇到 `IndexNode` 会**自己递归拆**，
  而不是交给普通 `_evaluate`（那会复制）；取格子用不复制版的 `read_index()`

**教训（本次最重要的一条）**：本项目的核心手法就是"到处 encode/decode 绕一圈"，
而 `decode` 会**造新对象**。所以"读"可以随便复制，"写"必须落到真对象上——
这两条路**从赋值的角度必须分开**。这是设计存储层时就该想清楚的事，
现在它以"第二条求值路径"的形式补上了。

## 关键字表：副本没有增加，但**语义分叉**了

第三版新增 5 个关键字（`break` `continue` `and` `or` `not`），
而各副本对它们的取舍**不一样**，这是本版的新情况：

| 文件 | 常量 | 要不要加这 5 个 |
|---|---|---|
| `pypython.py` | `KEYWORDS` | 全加（词法层要认出来） |
| `pypython.py` | `STATEMENT_KEYWORDS` | **只加 break/continue** |
| `pypython_idle/__init__.py` | `PYPYTHON_KEYWORDS` | 全加 |
| `pypython_idle/colorizer.py` | `PYPYTHON_KEYWORDS` | 全加（要染色） |
| `pypython_idle/hyperparser.py` | `PYPYTHON_KEYWORDS` | 全加 |
| `pypython_idle/autocomplete.py` | `completion_kwds` | 全加（要补全） |
| `pypython_idle/pyparse.py` | `PYPYTHON_BLOCK_OPENERS` | **一个都不加** |
| `pypython_idle/pyparse.py` | `_closere` | **只加 break/continue** |
| `pypython_idle/calltip.py` | `SYNTAX_CARDS` | 新增 4 张卡片 |
| `pypython_ide.py` | `PYPYTHON_KEYWORDS` / `COMPLETION_SKELETONS` | 全加 |

**为什么 `and`/`or`/`not` 绝不能进 `STATEMENT_KEYWORDS`**：
那张表的意思是"这个 token 能**开一条新语句**"。
`not` 进去的话，`if not x` 里的 `not` 会被当成一条新语句的开头，
整个 if 解析崩掉。`and`/`or` 同理。

**为什么 `break`/`continue` 绝不能进 `PYPYTHON_BLOCK_OPENERS`**：
那是"这个关键字后面要缩进"的意思。加进去的现象是
"写完 `break` 按回车，编辑器多缩进一级"——很难查。
（`pyparse.py` 第二版的注释里就留了一句
"将来加了 break，要把 _closere 加回来"，本次**按当时的预判**只改了 `_closere`。）

**`_closere` 反而必须加** `break`/`continue`：它们是块结束语句，
之后按回车缩进要回到块开头。注意用**整词**匹配，
否则 `continues` 这种变量名会被误判。

验证方式：`tests/test_keyword_sync.py`。
**本版把它的性质改了**——它原来只 `print` 比对结果、**从不返回非 0**，
于是"某份表少了一个关键字"在总入口里显示为 `[OK]`。
一个永远绿的测试比没有测试更坏，现在它逐项 `check()` 并在失败时 `exit(1)`。

## 受影响代码

解释器 `pypython.py`：

- `KEYWORDS` +5；`SINGLE_SYMBOLS` / `RE_SYMBOL` 加 `{` `}` `:`（**#29 就出在这里**）
- `STATEMENT_KEYWORDS` +2（break/continue）
- 新增 AST 节点 7 个：`IndexNode` `DictNode` `IndexAssignStmt` `LogicNode`
  `NotNode` `BreakStmt` `ContinueStmt`
- 新增运行期信号 2 个：`BreakSignal` `ContinueSignal`
- `PyPyValue`：`encode`/`decode`/`_decode_one` 支持 `D` 前缀；
  新增 `_hashable()`（把不可哈希的 key 变成友好的中文报错）；
  新增 `truth_number()`（#28）
- `transmute_output` 新增字典分支
- Parser：新增 `_or()` / `_and()`，`_unary()` 接受 `not`，
  `_postfix_tail` 接受 `[`，`_atom_base` 接受 `{`，新增 `_dict_literal()`、
  `_finish_index_target()`、`_stmt_break()`、`_stmt_continue()`；
  `loop_depth` 字段（#26、#27）
- Interpreter：`_eval_index` / `_eval_dict` / `_eval_logic` / `_eval_not` /
  `_do_index_assign` / `write_index` / `read_index` / `_evaluate_container` /
  `_do_break` / `_do_continue`；`_do_while` / `_do_for` 接住两个信号；
  `_do_for` 支持遍历字典

IDE 侧：上表全部，外加 `calltip.py` 的 `_pick_card` 新增 4 条分派。

## 遗留

- 仍然没有：切片、`while ... else`、异常、`import`、`range()`
- 字典迭代期间的修改语义**未定义**（按复制出来的快照走，不报错）
- 字符串仍然不能用 `[]` 取字符（报了明确的错，指路 `for c in "..."`）
