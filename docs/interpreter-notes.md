## 这是什么

一个**寄生在 CPython 之上的解释器**，纯粹由 Python 代码构成。
它不替代 CPython，也不绕过 CPython —— 它坐在 CPython 上面，
把「1 毫秒能做完的事拖成 100 毫秒」。

项目代号 **pyPython**。设计哲学三条：

  · 把简单的东西复杂化
  · 把高效的东西低效化
  · 把能跑的东西整得不能跑

**输出不需要正确，但必须自洽。** 这不是 bug，是目标。

## pyPython-1 语法

```
a「1」              赋值。用 「」 代替等号，变量自动创建
a「a + 1」          重新赋值
$(a)               输出。用 $() 代替 print
~  ·               等于 / 不等于（同一个键位，不带 Shift 的是「不等于」）
>  <               大于 / 小于，与原意相同
(a + b) 2          并排即相乘 = (a+b)*2，**只在括号内生效**
(a + b) 2 3        = (a+b)*2*3，可以叠
[1, [2], "x"]      列表，可嵌套、可混类型
"abc" + "def"      字符串拼接，只能用双引号
if a ~ 1           用缩进划块，**没有冒号**
    $(42)
else
    $(0)
$(x) $(y)          一行两条语句，**没有分号**
```

`「」` 可以跨行，像括号一样。

## 刻意的"低效"设计

这些不是没优化，是**反向优化**，每一条都在代码里标了 `{意图：增加复杂度}`
或 `{意图：降低可读性}`：

  · **11 层装饰性优先级**（`_l11` → `_l1`），每层只做一件事
  · **真值格**（truthiness lattice）：`FALSE / HOPELESS / LIMBO / TRUE`，
    只有最高档算真。判个真假要走四层
    （第三档原名 `MAYBE`，第四版改名 `LIMBO`，见 ADR-0009）
  · **变量注册表**以**字符串列表**存放，每次读写都要序列化/反序列化
  · **每个节点访问都调 `reify()`**
  · **正则二次校验层**：已经 tokenize 过的东西再用正则验一遍
  · **手写二进制转换**输出，不用 `bin()`
  · **LogBook 账本**，`total()` / `census()` 都是 O(n)
  · 输出一律带全角装饰：`2 ⟨TRUE⟩ 0b10`
  · **三值逻辑**（第四版）：`TRUE / FALSE / MAYBE`，**这一层是真功能，不是装饰**

## 性能实测

与 CPython 比（口径不同结果差很多，两种都报）：

| 基线 | 口径 | 倍数 | 达标 |
|---|---|---|---|
| A | 只算执行（预编译 code object） | ≈ 474× | 是（2.7 个数量级） |
| B | 全流程（含编译，与 pyPython 同口径） | ≈ 11.9× | **否**（1.1 个数量级） |

B 没达标这件事**如实写在这里**，不粉饰。

## 硬约束：不许用宿主求值

**`exec` / `eval` 只允许出现在 `main()` 的性能基线测量里，绝不允许在执行路径上。**

这是 ADR-0001 的硬约束。验证方式是走 AST 检查所有 `ast.Call` 节点，
**不是字符串匹配** —— 注释里会引用这些词，字符串匹配会误判（踩过这个坑）。
守卫脚本是 `tests/test_adr0001_no_exec.py`。

## 代号说明

  · **泬**（U+6CEC）：抽象层次计数单位
  · **炑**（U+7091）：错误代号

## 已知取舍

  · `~` 和 `·` 在同一个键上。打反了**不会报错**（两个都是合法运算符），
    只会算错。这是已知设计，见 ADR-0002
  · `$(1+1)` 输出的 `0b10` 是**手写**的二进制转换，故意保留了这个"错"
  · 比较返回**真值格档位序号**（真=3，假=0），不是 1/0。见 `wiki/输出格式.md`
  · 三值逻辑的完整取舍见 ADR-0009 和 `wiki/已知限制.md`
