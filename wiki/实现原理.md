# 实现原理

解释器本体是 `pypython.py`（5539 行）。它分成 **12 个"抽象层"**，
每一层都标了 `{意图：增加复杂度}` 或 `{意图：降低可读性}`。

---

## 整体流程

```
源码字符串
   ↓  抽象层 5：Lexer          切 token，每个 token 后过 2 次正则
   ↓  抽象层 2：正则重验层      已经扫过的东西再用正则验一遍
   ↓  抽象层 6：Parser         11 层"装饰性优先级"+ 中缀解析
   ↓  抽象层 9：Interpreter    求值，五层调用 + 三次转换
   ↓  抽象层 7：真值密室        每个值都判一次真假
   ↓  抽象层 8：输出后处理      转二进制 → 套全角装饰
   ↓  抽象层 1：泬账本          每一步都记一笔
```

---

## 12 个抽象层

| 层 | 名称 | 干什么 |
|---|---|---|
| 1 | 泬单位 | 计数单位。1 泬 = 1 次无意义的字符串转换 |
| 2 | 正则重验层 | 已经 tokenize 过的东西，再用正则验一遍 |
| 3 | 符号注册表 | 变量存在**字符串列表**里，读写都要序列化 |
| 4 | 值的编码层 | 值 → 字符串 → 存起来，取出再解码 |
| 5 | 词法分析器 | 切 token |
| 6 | 语法分析器 | 11 层优先级（**优先级毫无意义**）+ 中缀解析 |
| 7 | 真值密室 | 每个值判一次真假，四档 |
| 7.5 | 三值逻辑门 | Kleene 真值表（**这层是正经功能**） |
| 7.6 | 静默观测账本 | 记录控制流碰到未知的次数和来源 |
| 8 | 输出后处理 | 手写二进制 + 全角装饰 |
| 9 | 解释执行器 | 求值 |
| 10 | 驱动器 | 把上面串起来，每段之间夹一次统计和打印 |

## 11 层"装饰性优先级"

`_l11` → `_l1`，每层只做一件事，**大部分层什么都没做**。

这是需求 3 的直接产物（"故意把简单的东西复杂化"）。
表达式求值从 `_l11` 开始一路往下穿 11 层。

**约束：改任何一层都要注意，实际的中缀优先级链条是**：

```
并排相乘 → _or → _and → 比较 → 加减 → 乘除 → _unary → 原子/后缀
```

`not` 坐在**比较之下**，所以 `not a ~ b` 等价于 `not (a ~ b)`。

## 值的编码（ADR-0003）

所有值在进注册表前必须**编码成字符串**。

```
S<长度>:<内容>              字符串
L<个数>:<元素...>           列表
D<对数>:<k><v><k><v>...     字典
N:<数值>                    数字
F<槽位> / C<槽位> / O<槽位>  函数 / 类 / 实例（走旁路登记表）
T<路径>|<上述任一>           被未知污染过的值
```

**为什么用长度前缀而不是分隔符**：早期用 `,` 拼接，
`[1, [2, [3]]]` 的内层列表本身就含逗号，被外层一刀切开就成了残缺片段，
于是所有嵌套列表静默变成 `[1, 0, [0]]`。（#13）

长度前缀让**元素边界由类型自己界定**，不依赖任何分隔符，
也不需要转义。

**约束**：没污染的值编码**完全不变**（`N:5` 就是 `N:5`），
这是三值逻辑的污染标记能向后兼容的原因。

## 真值密室

任何值都要经过密室，被"判定"成四档之一：

```
FALSE / HOPELESS / LIMBO / TRUE
```

规则（**完全是我们编的，且互相重叠**）：

| 输入 | 判定 |
|---|---|
| `0` | `FALSE` |
| 负数 | `HOPELESS` |
| 0 到 1 之间 | `LIMBO` |
| 其余 | `TRUE` |

字符串按**长度**判、列表按**元素个数**判、字典按**键值对个数**判、
函数/类/实例一律判 `0`（刻意不按参数个数，否则 `if 某个函数` 会因为
参数多而变真，太容易误解）。

**只有最高档 `TRUE` 算真**，其余三档行为完全相同——但你能问出是哪一档。
也就是说：**你问得出区别，却用不上区别。**

> 第四版把第三档从 `MAYBE` 改名成 `LIMBO`，
> 因为 `MAYBE` 这个名字让给"未观测"了。见 [三值逻辑](三值逻辑)。

## 一次 `1+1` 到底绕了多少路

### 9 层调用链

```
_execute          ← 语句分发
_do_assign        ← 赋值语义（含隐式注册）
_evaluate         ← 表达式分发
_eval_binop_node  ← 中缀运算（伪装成波兰式再算）
_apply_operator   ← 运算符分派（折叠）
_numeric_binary   ← 数值运算 + 密室审问
_coerce_operand   ← 强制转换
_materialize      ← 实体化（调用链终点）
```

### 5 次数据结构转换

```
源码字符串 → TokenEnvelope 对象（含正则验证宽度与指纹）
AST 节点 → shadow 字符串（reify，每访问一次做一次）
PyPyValue → "N:2" 编码字符串 → 注册表的 list
数字 → 字符串 → float → 真值字符串（真值密室）
数字 → 二进制字符串 → split 成 list → 重新拼回字符串
```

### 每 token ≥2 次正则匹配

```
Lexer 扫描完每个 token 后，revalidate() 内连续匹配 2 次
运行期 _eval_number 对同一个数字串再匹配 1 次
注册表解码时对编码串再匹配 1 次
```

## 手写二进制

输出里的 `0b10` **不是** `bin()` 算的：

```python
whole = int(abs(number))
if whole == 0:
    return "0b0"
digits = ""
remainder = whole
while remainder > 0:
    digit = remainder % 2
    digits = _HEX_DIGITS[digit] + digits   # 每步字符串拼接，O(n²)
    remainder = remainder // 2
```

**故意不用 `bin()`、不用 `format()`**——那算"内建加速手段"。

> 这个手写转换有个已知的"错"：负数的输出是 `-0b1` 这种形式。
> **刻意保留**，不改。

## 硬约束：不许用宿主求值

> **`exec` / `eval` 只允许出现在 `main()` 的性能基线测量里，
> 绝不允许在执行路径上。**

这是 [ADR-0001](https://github.com/Agying3/pyPython/blob/master/docs/decisions/0001-pyPython-宿主与定位.md)
的硬约束。

验证方式是**走 AST 检查所有 `ast.Call` 节点，不是字符串匹配**——
注释里会引用这些词，字符串匹配会误判（踩过这个坑）。
测试是 `tests/test_adr0001_no_exec.py`。

## 泬账本

每一步操作都往账本记一笔：

```python
class LogBook:
    def __init__(self):
        self.units = []          # 一个本该是 int 的计数器，被做成了对象列表

    def total(self):             # 手写 for 循环累加，不用 sum()
        accumulator = 0
        for unit in self.units:
            accumulator = accumulator + unit.mass()   # mass() 又是 3 次调用
        return accumulator

    def census(self):            # 又遍历一遍同一份列表，就为了打印时好看
        ...
```

`total()` 和 `census()` **各遍历一遍同一个列表**——同一个列表走两遍。
