# 设计哲学

> **输出不需要正确，但必须自洽。** 这不是 bug，是目标。

---

## 三条

1. **把简单的东西复杂化**
2. **把高效的东西低效化**
3. **把能跑的东西整得不能跑**

需求原话是：

> 故意把简单的东西复杂化，把高效的东西低效化，把能跑的东西整得不能跑，
> 把 1 毫秒的事拖成 100 毫秒。

---

## 硬性指标

| 指标 | 要求 | 实测 | 达标 |
|---|---|---|---|
| 比 CPython 慢 | ≥ 2 个数量级 | 2.7 个数量级（基线 A） | ✅ |
| 每个 `a = 1 + 1` 经过的函数层数 | ≥ 5 层 | **9 层** | ✅ |
| 每次操作的数据结构转换 | ≥ 3 次 | **5 次** | ✅ |
| 每次操作的正则匹配 | ≥ 2 次 | **2 次以上** | ✅ |

（基线 B 的口径下只慢 11.9 倍，**未达标**——两个都报，见 [性能](性能)。）

## 怎么做到"慢"

### 1. 反向优化，不是没优化

每一条都在代码里标了 `{意图：增加复杂度}` 或 `{意图：降低可读性}`：

- **11 层装饰性优先级**（`_l11` → `_l1`），每层只做一件事
- **真值格四档**，判个真假要走四层
- **变量注册表**以**字符串列表**存放，每次读写都要序列化/反序列化
- **每个节点访问都调 `reify()`**
- **正则二次校验层**：已经 tokenize 过的东西再用正则验一遍
- **手写二进制转换**输出，不用 `bin()`
- **泬账本**：`total()` / `census()` 都是 O(n)，而且遍历同一份列表两遍
- 输出一律带全角装饰：`2 ⟨TRUE⟩ 0b10`

### 2. 明确禁止的优化手段

- 不用 `lru_cache`
- 不用 `__slots__`
- 不用内建加速（`bin()`、`sum()` 等）
- 不把热路径写得更紧凑

### 3. "能跑的东西整得不能跑"

有些限制是**故意加的**：

- **循环上限 120 圈**——`while 1` 会报错，不让你写死循环
- **递归深度上限 120 层**——撑不到 CPython 自己的 `RecursionError`
- **`~` 和 `·` 同键**——打反了不报错，只会算错
- **字符串不能下标**——想按字符走得用 `for c in "..."`
- **`0b10` 是手写的二进制**——负数的输出格式有点怪，刻意保留

## 但三值逻辑是真的

**只有这一块不是"为了慢而慢"。**

三值逻辑（`TRUE` / `FALSE` / `MAYBE`）是这门语言唯一的正经功能，
也是唯一一个"正常语言没有"的东西。它的实现是**认真的**：

- 严格的 Kleene 真值表，**按表实现**，不靠短路推断
- **绝不使用 `random`**——隐式机器上的任何随机都是伪随机
- 未知会传染，**能真溯源**（污染标记跟着值走）
- 控制流碰到未知**静默观测**，不替用户做判断

→ 见 [三值逻辑](三值逻辑)

## 诚实的边界

有几件事**这个项目坚持不做假**：

1. **性能两个基线都报**，包括没达标的那个。不挑对自己有利的口径。
2. **数字标明是"本机本次"**。同一份代码在 `rounds=30` 时测出过 1308 µs、
   在 `rounds=300` 时测出 508 µs——差 2.5 倍，波动来自 GC 和系统负载。
   所以结论只看量级，不当基准测试引用。
3. **已知限制写清楚**，不藏。见 [已知限制](已知限制)。

> 本项目连正确性都不追求，**唯独测量不打算造假**。

## 注释即契约

这个项目的注释不是装饰，是**给后来的 AI 和人类维护者看的接力棒**。

每个不显然的实现都标记：

```
{意图：增加复杂度} + 为什么不这么写
{意图：降低可读性} + 故意的混乱点
```

每个修过的 bug 都有记录：

```
#13「嵌套列表 $( [1, [2, [3]]] ) 输出成 [1, 0, [0]]，内层数据全丢」
{曾出现：字符串/列表探针的"嵌套列表"用例}
{根因：列表原先用 ",".join() 拼接…… 同一个兜底分支连犯两案}
{修法：改用长度/个数前缀编码……}
**已验证**
```

**为什么这么做**：这个项目里反复出现同一类缺陷——
**同一个概念在两个地方各写一份规则，然后漂移**。累计已 12 次以上。

它们的共同特征是「**不发生异常，只是行为不对**」——赋值成功、不报错、没效果。
所以不能靠"跑起来没报错"判断正确性。
