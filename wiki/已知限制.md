# 已知限制

这一页列**明确不支持**的东西，以及**故意的坑**。

> 原则：**报错，不静默失败**。不支持的功能写出来会有明确的「炑」错误，
> 而不是悄悄算错。

---

## 语言功能缺失

| 功能 | 现状 | 替代方案 |
|---|---|---|
| **切片** `xs[0:2]` | ❌ 不支持 | 用 `for` 取 |
| **异常** `try/except` | ❌ 不支持 | 无 |
| **`import`** | ❌ 不支持 | 无（没有模块系统） |
| **`range()`** | ❌ 不支持 | 用字面量列表 `[0,1,2]` |
| **继承** `class B(A)` | ❌ 不支持 | 组合 |
| **`lambda`** | ❌ 不支持 | 用 `def` |
| **`while...else`** | ❌ 不支持 | 无 |
| **`for...else`** | ❌ 不支持 | 无 |
| **`elif`** | ❌ 不支持 | 嵌套 `else` + `if` |
| **字符串下标** `s[0]` | ❌ 不支持 | `for c in "..."` |
| **`//` `%` `**`** | ❌ 不支持 | 无 |
| **`+=` `-=`** | ❌ 不支持 | 写全 `x「x + 1」` |
| **多行注释** | ❌ 不支持 | 每行 `#` |
| **元组 / 集合** | ❌ 不支持 | 用列表 |
| **参数默认值** | ❌ 不支持 | 重载（也不支持） |
| **多返回值** | ❌ 不支持 | 返回列表 |

写这些的报错信息（实测）：

```
切片        → 下标缺少收尾的 ']'
异常        → 变量 'try' 之后期待 '「'
import      → 变量 'import' 之后期待 '「'
range       → 名字 'range' 从未被 manifest 过
继承        → 语句结尾期待换行，却遇到 '('
lambda      → 赋值缺少收尾的 '」'
字符串下标   → 字符串不能用 [] 取字符（本语言没有这个功能）；
              想按字符走请用 for c in "..."
```

> `range` 那条错误信息挺妙：**"从未被 manifest 过"**——
> 把变量注册表那套术语直接漏给用户了。

## 故意的坑

这些**不是 bug，是设计**：

### `~` 和 `·` 在同一个键上

```
~                  等于（按 Shift）
·                  不等于（直接打）
```

**打反了不报错**——两个都是合法运算符，只是意思相反，所以会**静默算错**。

为什么这么设计：用户定的。代价是中文输入法下容易打反。

> 代码里留了提示的位置注释（`Parser._compare`），但**本版没实现检测**。

### 循环上限 120 圈

```
while 1
    $(1)           炑报错：循环超过 120 圈还没停
```

**故意的**——"把能跑的东西整得不能跑"。不让你写死循环。

### 递归深度上限 120 层

比 CPython 自己的 `RecursionError` 先到。所以你看到的是本语言的错误，
不是宿主的。

### 负数二进制是 `-0b1`

```
$(-1)              → -1 ⟨HOPELESS⟩ -0b1
```

手写二进制转换的一个"错"。**用户明确要求保留，不要"修"它。**

### 真 = 3，不是 1

比较返回真值格的**档位序号**：

```
$(1 ~ 1)           → 3 ⟨TRUE⟩ 0b11
```

跟 Python 的 `True == 1` 不一样。见 [输出格式](输出格式)。

### 字符串不能用 `[]`

明确报错，而且**告诉你怎么办**：

```
$(s[0])            炑报错：字符串不能用 [] 取字符；
                        想按字符走请用 for c in "..."
```

## 三值逻辑的取舍

| 项 | 现状 | 说明 |
|---|---|---|
| **`x ~ x`** | 返回 `MAYBE` | 不确定的东西不能声称自己等于自己（用户确认保持） |
| **污染标记不会自动清除** | 值脏了就带着 | 真正的"污点清除"需要显式机制，本版没做 |
| **溯源粒度是变量** | `y「x+1」` 记成 `x>y` | 中间的 `+1` 不体现 |
| **比较不参与真值表** | `未知 ~ 未知` → `MAYBE` | 超出 Kleene 标准表，是本项目自定的 |
| **`未知 + "a"`** | 返回 `MAYBE` | 被算术拦截，没细究"该不该报类型错" |

**`x ~ x` 保持 MAYBE 的副作用**：用户没办法写"这个值到底观没观测"的
自反判断。要做那个得另加一个 `已观测(x)` 之类的内建，本版没有。

## 代码层面的已知取舍

- **`interpreter.py` 是早期的正经计算器解释器**，与本语言无关，已搁置。
  `docs/extension-design.md` 讲的是它的扩展，**不是 pyPython 的**。
- **`docs/interpreter-notes.md` 的部分数字已过期**（写的是 2985 行、
  真值格还是 `MAYBE`）。以代码和 ADR 为准。
- **`未知` 必须排在输出分派的最前面**（在字符串分支之前），
  否则会被按长度判成 `TRUE`。改输出流程时别把它挪下去。

---

## 为什么写这一页

因为**"不支持"和"没做"是两回事**，用户需要分得清：

- **不支持**：设计上就不要，报错明确 → 这一页
- **没做**：想要但还没做 → 也在这页，但会写清楚

而**故意的坑**必须单独标出来，否则下一个维护者会热情地把它们"修好"。
